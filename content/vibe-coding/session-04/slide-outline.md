수업 개요
* 주제: 아이디어를 구체적인 기획서(PRD)로 정리하고, AI에게 전달하여 앱의 뼈대를 생성하기
* 시간: 100분 (도입 15분 / 이론 15분 / 실습 60분 / 마무리 10분)
* 결과물: 나만의 프로젝트 기획서(PRD) + AI가 생성한 앱 뼈대 코드
* 준비물: 크롬 브라우저, 구글 계정, 아이디어 메모
슬라이드 1 표지
* 제목: 4회차 — 내 아이디어를 설계도로
* 부제: 코딩보다 중요한 것? 기획!
* 과정명: Gemini와 함께하는 바이브 코딩 입문
슬라이드 2 오늘 수업에서 할 것
* 각자 생각해온 아이디어 발표 & 주제 확정
* 기획서(PRD)를 쓰는 법 배우기
* 내 기획서를 AI에게 전달해서 앱의 첫 번째 뼈대 받기
* 오늘의 결과물: 기획서 + AI가 만든 앱 뼈대 코드
슬라이드 3 도입 — 아이디어 발표 타임 (강사용 교안)
* 소요시간: 15분
* 활동: 각자 준비해온 아이디어 2~3개를 한 명당 1분 내외로 발표
* 강사 멘트: "오늘부터 여러분만의 프로젝트를 시작합니다! 지난 시간에 생각해온 아이디어를 발표해주세요. 한 명당 1분! 뭘 만들고 싶은지, 누가 쓸 건지, 왜 만들고 싶은지를 간단히 말해주면 됩니다."
* 피드백 방식: 발표 후 강사와 친구들이 한마디씩 피드백
* "이거 진짜 쓰고 싶다!", "기능을 좀 줄이면 만들기 쉬울 것 같아", "이 아이디어에 OO을 추가하면 어떨까?"
* 주제 확정: 발표 후 각자 최종 주제 1개를 선택
* 강사 유의사항: 너무 복잡하거나 데이터베이스(서버)가 필요한 아이디어는 범위를 줄이도록 조언. "한 페이지 안에서 동작하는 것"을 기준으로 안내. 아이디어가 없는 학생에게는 추천 목록에서 고르게 한다.
* 추천 프로젝트 리스트 (못 정하는 학생용):
* (쉬움) MBTI 궁합 테스트: 두 MBTI 입력 → 궁합 결과 & 조언
* (쉬움) 시험 D-day 카운트다운: 시험 이름+날짜 입력 → 남은 일수 표시
* (쉬움) 랜덤 벌칙 룰렛: 벌칙 목록 → 버튼 누르면 룰렛 돌아감
* (보통) 급식 별점 리뷰: 메뉴에 별점+한줄평 남기기
* (보통) 오늘의 명대사 생성기: 카테고리 선택 → 랜덤 명대사 표시
* (보통) 감정 일기장: 감정 이모지 선택 → 한줄 일기 → 기록 보기
* (도전) 나만의 퀴즈 메이커: 질문+답 입력 → 퀴즈 웹앱 생성
슬라이드 4 이론 — 왜 기획이 코딩보다 먼저인가? (이론 페이지)
* 소요시간: 이론 15분 중 전반부
* 바이브 코딩의 성공 비결 = 잘 쓴 기획서(PRD)
* AI는 시키는 대로 한다. 그런데 "시키는 것"이 불명확하면 결과도 불명확하다
* 기획서 = AI에게 전달할 "완벽한 주문서"
* 비유: 집을 지을 때 설계도(기획서) 없이 "집 지어줘"라고 하면 어떻게 될까? → 방 몇 개인지, 어디에 부엌이 있는지, 창문은 몇 개인지 정해야 함
* AI 리터러시 핵심 포인트:
* AI가 아무리 똑똑해도 "무엇을 만들지"를 결정하는 건 사람만 할 수 있다
* 여러분은 감독이자 기획자. AI는 훌륭한 실행팀(인턴). 감독이 명확한 비전을 주지 않으면 아무리 뛰어난 팀이어도 좋은 영화가 나올 수 없다
* 바이브 코딩에서 가장 중요한 세 가지: (1) 사용자 흐름 — 사용자가 앱을 어떤 순서로 쓰는지 (2) 실패 사례 — 뭔가 잘못될 때 어떻게 되어야 하는지 (3) 제약 조건 — 어떤 기술, 어떤 디자인을 쓸 것인지
슬라이드 5 이론 — 간단한 PRD 작성법 (이론 페이지)
* PRD란? = Product Requirements Document = 제품 요구사항 문서 = "내 앱의 설계도"
* 어렵게 생각하지 말고, 아래 6가지 항목을 채우면 된다:
* (1) 앱 이름: (예: "MBTI 매칭 테스트")
* (2) 한 줄 소개: (예: "두 사람의 MBTI를 입력하면 궁합과 조언을 알려주는 웹앱")
* (3) 대상: (예: "MBTI에 관심 많은 고등학생 친구들")
* (4) 주요 기능 3가지:
* 기능 1: 두 사람의 MBTI를 선택할 수 있는 드롭다운 메뉴
* 기능 2: "궁합 보기" 버튼을 누르면 궁합 점수(%)와 설명이 나타남
* 기능 3: 결과를 카카오톡으로 공유할 수 있는 "공유" 버튼
* (5) 화면 구성:
* 첫 화면: 제목 + 두 MBTI 선택란 + "궁합 보기" 버튼
* 결과 화면: 궁합 점수 + 설명 + 공유 버튼
* (6) 디자인 느낌: (예: "귀엽고 밝은 파스텔톤, 이모지 많이, 둥근 모서리")
* 쉬운 풀이 박스:
* PRD(Product Requirements Document) = 제품 요구사항 문서. 앱을 만들기 전에 "이 앱은 이래야 한다"를 정리한 설계도
* 사용자 흐름(User Flow) = 사용자가 앱을 쓰는 순서. "먼저 이걸 누르고 → 그 다음 이걸 입력하고 → 그러면 이게 나온다"
* 드롭다운(Dropdown) = 클릭하면 목록이 펼쳐지는 선택 메뉴
슬라이드 6 이론 — PRD 예시: 좋은 것 vs 애매한 것 (이론 페이지)
* 애매한 기획서:
* "MBTI 앱 만들어줘. 예쁘게 해줘."
* → AI가 마음대로 만들어서 내가 원하던 것과 다를 가능성이 높음
* 좋은 기획서:
* 앱 이름: MBTI 궁합 테스트
* 한 줄 소개: 두 사람의 MBTI를 입력하면 궁합 점수와 조언을 보여주는 웹앱
* 대상: MBTI에 관심 많은 고등학생
* 주요 기능: (1) MBTI 16가지 중 2개 선택 (2) 궁합 점수(%)와 한줄 해석 (3) 다시하기 버튼
* 화면 구성: 메인 화면에 제목, MBTI 2개 선택, 궁합 보기 버튼. 결과 화면에 점수+해석+다시하기 버튼
* 디자인: 분홍색+보라색 그라데이션 배경, 둥근 카드 형태, 이모지 활용, 큰 글씨
* → AI가 정확히 이해하고 의도에 맞는 결과를 만들어줌

슬라이드 9 실습 1 — 나만의 기획서(PRD) 작성하기 (실습 페이지)
* 소요시간: 25분
* 활동지의 PRD 양식에 맞춰 6가지 항목을 채운다:
* (1) 앱 이름
* (2) 한 줄 소개
* (3) 대상 (누가 쓸 것인가?)
* (4) 주요 기능 3가지 (버튼을 누르면 뭐가 되는지 등)
* (5) 화면 구성 (어떤 화면이 있고, 각 화면에 뭐가 있는지)
* (6) 디자인 느낌 (색상, 분위기, 참고 이미지)
* 작성 팁:
* "버튼을 누르면 ~이 나타난다", "입력창에 ~를 쓰면 ~가 계산된다"처럼 동작 중심으로 쓰기
* 기능이 너무 많으면 가장 중요한 3가지만 우선 적기 (나머지는 6회차에 추가 가능)
* 화면 구성은 글로 쓰거나, 종이에 대충 그림을 그려봐도 좋다
* 강사 활동: 돌아다니면서 1:1로 기획서 피드백
* 체크포인트: "이 기획서만 읽고 앱이 뭔지 바로 이해되는가?", "기능이 너무 많지 않은가?", "화면 구성이 구체적인가?"
* 피드백 예시: "여기 '예쁘게'라고 썼는데, 어떤 색상인지 구체적으로 적어보면 어떨까?", "기능이 5개인데, 가장 중요한 3개만 먼저 하고 나머지는 나중에 추가하자"

슬라이드 12 실습 2 — 기획서를 AI에게 전달하기 (실습 페이지)
* 소요시간: 25분
* 방법: 기획서를 프롬프트 형태로 Google AI Studio에 입력
* 프롬프트 템플릿:
아래는 내가 만들고 싶은 웹앱의 기획서야.
이 기획서를 바탕으로 HTML, CSS, JavaScript를 하나의 파일에 합쳐서
웹앱의 기본 구조(뼈대)를 만들어줘.
아직 완벽하지 않아도 괜찮아. 기본 화면과 레이아웃이 나오면 돼.
여기에 기획서 6가지 항목을 전부 붙여넣기
* AI의 결과를 코드로 받으면:
* 코드를 복사 → .html 파일로 저장 → 브라우저에서 실행
* 기획서 대비 뭐가 맞고 뭐가 빠졌는지 확인!
슬라이드 13 실습 2 — 결과 확인 & 보완 요청 (실습 페이지)
* 확인 체크리스트:
* 기획서에 적은 화면 구성이 반영되었는가?
* 주요 기능 3가지가 포함되었는가? (아직 동작 안 해도 버튼이라도 있는가?)
* 디자인 느낌이 요청한 것과 비슷한가?
* 빠진 부분이 있다면?
* 빠진 부분을 추가 프롬프트로 보완 요청하기:
* 예시: "기획서에 적은 '다시하기 버튼'이 빠져있어. 결과 화면 하단에 추가해줘"
* 예시: "배경색을 분홍색 그라데이션으로 바꿔줘. 기획서에 적은 대로"
* 예시: "제목 폰트를 더 크고 귀여운 느낌으로 바꿔줘"
* 강사 멘트: "기획서와 결과물을 비교해보세요. 기획서가 구체적이었던 부분은 잘 반영되었고, 대충 쓴 부분은 AI가 마음대로 했을 거예요. 이게 바로 기획의 힘입니다!"
* AI 리터러시 포인트: "보세요, AI는 여러분이 적은 대로 만들어줬어요. 잘 나온 부분은 기획서가 구체적이었기 때문이고, 이상한 부분은 기획서가 애매했기 때문이에요. 결국 기획을 잘하는 사람이 AI를 가장 잘 쓰는 사람입니다."
