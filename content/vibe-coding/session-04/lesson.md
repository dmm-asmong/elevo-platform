# 4회차 — 내 아이디어를 설계도로

> **오늘의 핵심 메시지:** ==기획이 코딩보다 먼저다. AI에게 완벽한 주문서를 전달하는 사람이 AI를 가장 잘 쓰는 사람이다.==

---

## 📋 오늘 수업에서 할 것

오늘은 머릿속 아이디어를 AI가 이해할 수 있는 설계도로 바꾸는 날입니다.

- 각자 생각해온 아이디어 발표 & 주제 확정
- 기획서(PRD)를 쓰는 법 배우기
- 내 기획서를 AI에게 전달해서 앱의 첫 번째 뼈대 받기
- 오늘의 결과물: ==기획서 + AI가 만든 앱 뼈대 코드==

---

## 💡 왜 기획이 코딩보다 먼저인가?

### 바이브 코딩의 성공 비결

바이브 코딩에서 가장 중요한 것은 코딩 실력이 아니라 ==잘 쓴 기획서(PRD)==입니다.

AI는 시키는 대로 합니다. 그런데 "시키는 것"이 불명확하면 결과도 불명확합니다.

> **기획서 = AI에게 전달할 "완벽한 주문서"**

### 설계도 없이 집을 지으면?

집을 지을 때 설계도(기획서) 없이 "집 지어줘"라고 하면 어떻게 될까요?

- 방이 몇 개인지 정해야 합니다
- 어디에 부엌이 있는지 정해야 합니다
- 창문은 몇 개인지 정해야 합니다

이처럼 AI에게도 구체적인 설계도를 주어야 원하는 결과를 얻을 수 있습니다.

### AI 리터러시 핵심

| 역할 | 누가 담당하는가? |
|------|----------------|
| "무엇을 만들지" 결정 | 오직 사람(여러분)만 할 수 있음 |
| 실행 (코딩, 구현) | AI가 담당 |

여러분은 ==감독이자 기획자==이고, AI는 훌륭한 실행팀(인턴)입니다. 감독이 명확한 비전을 주지 않으면 아무리 뛰어난 팀이어도 좋은 결과물이 나올 수 없습니다.

### 바이브 코딩에서 가장 중요한 세 가지

| 항목 | 설명 |
|------|------|
| ==사용자 흐름== | 사용자가 앱을 어떤 순서로 쓰는지 |
| ==실패 사례== | 뭔가 잘못될 때 어떻게 되어야 하는지 |
| ==제약 조건== | 어떤 기술, 어떤 디자인을 쓸 것인지 |

## 📝 PRD란 무엇인가?

### 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| ==PRD== (Product Requirements Document) | 제품 요구사항 문서. 앱을 만들기 전에 "이 앱은 이래야 한다"를 정리한 설계도 |
| ==사용자 흐름== (User Flow) | 사용자가 앱을 쓰는 순서. "먼저 이걸 누르고 → 그 다음 이걸 입력하고 → 그러면 이게 나온다" |
| ==드롭다운== (Dropdown) | 클릭하면 목록이 펼쳐지는 선택 메뉴 |
| ==프론트엔드== (Frontend) | 사용자가 눈으로 보고 직접 조작하는 화면 부분 |

### PRD 6가지 항목

어렵게 생각하지 말고, 아래 6가지 항목만 채우면 됩니다.

1. **앱 이름** — (예: "MBTI 매칭 테스트")
2. **한 줄 소개** — (예: "두 사람의 MBTI를 입력하면 궁합과 조언을 알려주는 웹앱")
3. **대상** — (예: "MBTI에 관심 많은 고등학생 친구들")
4. **주요 기능 3가지** — 버튼을 누르면 뭐가 되는지 등
5. **화면 구성** — 어떤 화면이 있고, 각 화면에 뭐가 있는지
6. **디자인 느낌** — (예: "귀엽고 밝은 파스텔톤, 이모지 많이, 둥근 모서리")

## ⚖️ 좋은 기획서 vs 애매한 기획서

### 비교로 배우는 PRD 품질

| 구분 | 내용 | 결과 |
|------|------|------|
| 애매한 기획서 | "MBTI 앱 만들어줘. 예쁘게 해줘." | AI가 마음대로 만들어서 내가 원하던 것과 다를 가능성이 높음 |
| ==좋은 기획서== | 6가지 항목을 구체적으로 채운 것 | AI가 정확히 이해하고 의도에 맞는 결과를 만들어줌 |

### 좋은 기획서 예시 (MBTI 궁합 테스트)

- **앱 이름:** MBTI 궁합 테스트
- **한 줄 소개:** 두 사람의 MBTI를 입력하면 궁합 점수와 조언을 보여주는 웹앱
- **대상:** MBTI에 관심 많은 고등학생
- **주요 기능:**
  1. MBTI 16가지 중 2개 선택
  2. 궁합 점수(%)와 한줄 해석
  3. 다시하기 버튼
- **화면 구성:** 메인 화면에 제목, MBTI 2개 선택, 궁합 보기 버튼 / 결과 화면에 점수+해석+다시하기 버튼
- **디자인:** 분홍색+보라색 그라데이션 배경, 둥근 카드 형태, 이모지 활용, 큰 글씨

## 🛠️ 실습 1 — 나만의 기획서(PRD) 작성하기

### 작성 방법

활동지의 PRD 양식에 맞춰 6가지 항목을 채웁니다.

1. 앱 이름
2. 한 줄 소개
3. 대상 (누가 쓸 것인가?)
4. 주요 기능 3가지 (버튼을 누르면 뭐가 되는지 등)
5. 화면 구성 (어떤 화면이 있고, 각 화면에 뭐가 있는지)
6. 디자인 느낌 (색상, 분위기, 참고 이미지)

### 작성 팁

- "버튼을 누르면 ~이 나타난다", "입력창에 ~를 쓰면 ~가 계산된다"처럼 !!동작 중심으로 쓰기!!
- 기능이 너무 많으면 가장 중요한 3가지만 우선 적기 (나머지는 6회차에 추가 가능)
- 화면 구성은 글로 쓰거나, 종이에 대충 그림을 그려봐도 좋다

### 교차 검토 활동

기획서를 작성한 후, 옆 친구와 기획서를 교환해서 읽어보세요.

검토할 때 이 질문을 사용하세요:
- "이 기획서만 읽고 어떤 앱인지 바로 이해가 되나요?"
- "빠진 정보가 있다면 뭘까요?"
- "이 앱을 쓰고 싶은 마음이 드나요?"

> **핵심:** 친구가 이해 못하는 기획서는 AI도 이해 못합니다. 사람에게 설명이 안 되면 AI에게도 안 되는 거예요.

## 🤖 실습 2 — 기획서를 AI에게 전달하기

### 프롬프트 작성 방법

기획서를 아래 프롬프트 형태로 Google AI Studio에 입력합니다.

```prompt
아래는 내가 만들고 싶은 웹앱의 기획서야.
이 기획서를 바탕으로 HTML, CSS, JavaScript를 하나의 파일에 합쳐서
웹앱의 기본 구조(뼈대)를 만들어줘.
아직 완벽하지 않아도 괜찮아. 기본 화면과 레이아웃이 나오면 돼.

[여기에 기획서 6가지 항목을 전부 붙여넣기]
```

### AI 결과 받은 후 처리 방법

1. 코드를 복사한다
2. `.html` 파일로 저장한다
3. 브라우저에서 실행한다
4. ==기획서 대비 뭐가 맞고 뭐가 빠졌는지 확인!==

### 결과 확인 체크리스트

| 항목 | 확인 방법 |
|------|-----------|
| 화면 구성 반영 여부 | 기획서에 적은 화면이 나타나는가? |
| 주요 기능 3가지 포함 여부 | 아직 동작 안 해도 버튼이라도 있는가? |
| 디자인 느낌 | 요청한 것과 비슷한가? |

### 빠진 부분 보완 요청 예시

결과물에서 빠진 부분이 있다면 추가 프롬프트로 보완 요청합니다.

```prompt
기획서에 적은 '다시하기 버튼'이 빠져있어. 결과 화면 하단에 추가해줘.
```

```prompt
배경색을 분홍색 그라데이션으로 바꿔줘. 기획서에 적은 대로.
```

```prompt
제목 폰트를 더 크고 귀여운 느낌으로 바꿔줘.
```

> **AI 리터러시 포인트:** 잘 나온 부분은 기획서가 구체적이었기 때문이고, 이상한 부분은 기획서가 애매했기 때문입니다. ==결국 기획을 잘하는 사람이 AI를 가장 잘 쓰는 사람입니다.==

## ✅ 오늘의 핵심 정리

1. ==PRD(기획서)== 는 AI에게 전달하는 완벽한 주문서다. 구체적일수록 결과가 좋다.
2. 바이브 코딩에서 여러분은 ==감독이자 기획자==다. AI는 실행팀이다.
3. 좋은 기획서의 핵심: ==사용자 흐름, 기능 목록, 화면 구성, 디자인 느낌== 4가지를 구체적으로
4. 사람에게 설명이 안 되는 기획서는 AI에게도 안 된다.
5. AI 결과물을 기획서와 비교하면서 부족한 부분을 추가 프롬프트로 보완한다.
