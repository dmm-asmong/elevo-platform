* 과제 발표: 2~3명의 아이디어를 간단히 발표
슬라이드 4 이론 — 프롬프트 엔지니어링이란? (이론 페이지)
* 소요시간: 이론 20분 중 전반부
* 프롬프트 엔지니어링(Prompt Engineering)이란?
* AI에게 내가 원하는 결과를 정확하게 얻어내기 위해 질문이나 명령(프롬프트)을 잘 작성하는 기술
* 쉽게 말하면: "AI에게 잘 말하는 기술". 같은 AI라도 어떻게 물어보느냐에 따라 결과의 품질이 완전히 달라진다
* 비유: 같은 식재료(AI의 능력)로도 레시피(프롬프트)에 따라 맛집 요리가 되기도 하고, 실패작이 되기도 함
* 왜 중요한가?
* AI는 읽은 그대로 이해한다 — 여러분의 머릿속 의도를 스스로 추측하지 못함
* 프롬프트를 잘 쓰는 것 = 내 생각을 명확하게 정리하는 것 = 기획력의 핵심
슬라이드 5 이론 — 좋은 프롬프트의 4가지 요소 (이론 페이지)
* 좋은 프롬프트의 구성 요소 4가지:
* (1) 역할(Role) 부여하기: "너는 ~야"
* 예: "너는 10년 경력의 웹 디자이너야"
* AI에게 특정 전문가 역할을 부여하면, 그 분야에 맞는 수준 높은 답변을 함
* (2) 구체적인 목표(Task): "~해줘"
* 뭘 해야 하는지 명확하게 지시
* 나쁜 예: "뭔가 만들어줘" → 좋은 예: "학교 동아리 모집 포스터 HTML을 만들어줘"
* (3) 맥락/배경정보(Context): "상황은 ~이야"
* AI가 상황을 이해할 수 있도록 추가 정보 제공
* 예: "대상은 고등학생이고, 밝고 활기찬 느낌으로 만들어야 해"
* (4) 출력 형식(Format): "~형태로 보여줘"
* 결과물의 형태를 지정
* 예: "HTML 코드로 작성해줘", "3줄 이내로 요약해줘", "표로 정리해줘"
* 쉬운 풀이 박스:
* 역할(Role) = AI에게 "너는 누구야"라고 정해주는 것. 전문가 역할을 주면 답변 품질이 올라감
* 맥락(Context) = 배경 상황, 조건, 대상 등 AI가 참고할 추가 정보
슬라이드 6 이론 — 제로샷 vs 퓨샷 프롬프팅 (이론 페이지)
* 소요시간: 이론 20분 중 후반부
* 제로샷(Zero-shot) 프롬프팅:
* 예시를 하나도 주지 않고 지시만 하는 방식
* "오늘 급식 메뉴를 맛집 리뷰처럼 써줘"
* 간단한 작업에 적합, 하지만 AI가 내 의도를 100% 파악하지 못할 수 있음
* 퓨샷(Few-shot) 프롬프팅:
* 원하는 결과의 예시를 1~3개 함께 보여주는 방식
* "아래 예시처럼 오늘 급식 메뉴를 리뷰해줘. 예시: '오늘의 돈까스는 겉바속촉! 소스가 짭짤달콤해서 밥도둑입니다. 별점 4.5/5'"
* AI가 예시의 스타일과 톤을 따라하기 때문에 원하는 결과에 더 가까워짐
* 쉬운 풀이 박스:
* 제로샷(Zero-shot) = 예시 없이 바로 지시하기. "이것 좀 해줘"
* 퓨샷(Few-shot) = 예시를 보여주고 "이런 식으로 해줘". 예시가 적으면 1~2개(Few), 많으면 여러 개
* 어떤 게 더 좋은 건 아님 — 상황에 따라 골라 쓰면 됨
슬라이드 7 이론 — 나쁜 프롬프트 vs 좋은 프롬프트 비교 (이론 페이지)
* 비교 예시 1:
* 나쁜 프롬프트: "포스터 만들어줘"
* 좋은 프롬프트: "너는 그래픽 디자이너야. 우리 학교 코딩 동아리 신입부원 모집 포스터를 HTML로 만들어줘. 대상은 고1~고2 학생이고, 밝고 재미있는 느낌으로 해줘. 동아리 이름은 'Code Vibes', 활동 내용은 바이브 코딩으로 앱 만들기. 지원 마감은 4월 30일이야."
* 비교 예시 2:
* 나쁜 프롬프트: "웹사이트 만들어줘"
* 좋은 프롬프트: "고등학생이 사용할 시험 D-day 카운트다운 웹페이지를 만들어줘. HTML, CSS, JavaScript를 하나의 파일에 작성하고, 시험 이름과 날짜를 입력하면 남은 일수를 큰 글씨로 보여줘. 배경은 깔끔한 하얀색, 폰트는 귀여운 느낌으로."
* 핵심: 구체적일수록 AI가 더 정확하게 알아듣는다!

슬라이드 10 실습 1 — 비포&애프터 챌린지 (실습 페이지)
* 미션 A: "학교 동아리 모집 포스터 HTML 만들기"
* 1차 시도(나쁜 프롬프트): "동아리 포스터 만들어줘" → 결과 확인
* 2차 시도(좋은 프롬프트): 역할 + 구체적 목표 + 맥락 + 형식을 모두 포함해서 다시 요청 → 결과 비교
* 미션 B: "오늘 급식 메뉴를 맛집 리뷰처럼 써줘"
* 1차 시도: "급식 리뷰 써줘" → 결과 확인
* 2차 시도: 오늘 실제 급식 메뉴를 적고, 퓨샷(예시 포함)으로 요청 → 결과 비교
* 미션 C: "내 방 정리 체크리스트 웹페이지 만들기"
* 1차 시도: "체크리스트 만들어줘" → 결과 확인
* 2차 시도: 체크 항목, 디자인, 체크하면 줄이 그어지는 기능까지 구체적으로 요청 → 결과 비교
* 강사 유의사항: 미션 3가지를 모두 못하면 1~2개만 해도 괜찮다고 안내. 속도가 빠른 학생은 3개 다 하도록.
