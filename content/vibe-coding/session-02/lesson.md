# 2회차 — 말을 잘해야 일을 잘 시킨다

> **오늘의 핵심 메시지:** ==AI가 못 알아듣는 게 아니라, 내가 잘 못 말한 거다!==

---

## 🎯 프롬프트 엔지니어링이란?

### 정의

==프롬프트 엔지니어링(Prompt Engineering)==이란, AI에게 내가 원하는 결과를 정확하게 얻어내기 위해 질문이나 명령(프롬프트)을 잘 작성하는 기술이다.

쉽게 말하면: **"AI에게 잘 말하는 기술"**

같은 AI라도 어떻게 물어보느냐에 따라 결과의 품질이 완전히 달라진다.

### 비유로 이해하기

> 같은 식재료(AI의 능력)로도 레시피(프롬프트)에 따라 맛집 요리가 되기도 하고, 실패작이 되기도 한다.

편의점 알바에게 "뭔가 맛있는 거 줘"라고 하면 뭘 줄까? 사람에게도 구체적으로 말해야 원하는 걸 받을 수 있듯이, AI도 마찬가지다.

### 왜 중요한가?

- AI는 읽은 그대로 이해한다 — 여러분의 머릿속 의도를 스스로 추측하지 못한다.
- 프롬프트를 잘 쓰는 것 = 내 생각을 명확하게 정리하는 것 = !!기획력의 핵심!!

---

## 📐 좋은 프롬프트의 4가지 요소

좋은 프롬프트는 아래 4가지 요소를 포함할수록 결과가 정확해진다.

| 요소 | 역할 | 예시 |
|------|------|------|
| ==역할 (Role)== | AI에게 "너는 누구야"라고 정해주는 것 | "너는 10년 경력의 웹 디자이너야" |
| ==목표 (Task)== | 뭘 해야 하는지 명확하게 지시 | "학교 동아리 모집 포스터 HTML을 만들어줘" |
| ==맥락 (Context)== | AI가 상황을 이해할 수 있도록 추가 정보 제공 | "대상은 고등학생이고, 밝고 활기찬 느낌으로" |
| ==형식 (Format)== | 결과물의 형태를 지정 | "HTML 코드로 작성해줘", "표로 정리해줘" |

### 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| 프롬프트 (Prompt) | AI에게 입력하는 질문이나 명령 |
| 프롬프트 엔지니어링 | AI에게 잘 말하는 기술. 원하는 결과를 얻도록 프롬프트를 설계하는 것 |
| 역할 (Role) | AI에게 "너는 누구야"라고 정해주는 것. 전문가 역할을 주면 답변 품질이 올라감 |
| 맥락 (Context) | 배경 상황, 조건, 대상 등 AI가 참고할 추가 정보 |

## ⚡ 제로샷 vs 퓨샷 프롬프팅

프롬프트 방식은 크게 두 가지로 나뉜다.

| 방식 | 설명 | 특징 |
|------|------|------|
| ==제로샷 (Zero-shot)== | 예시 없이 바로 지시하기 | 간단한 작업에 적합. AI가 의도를 100% 파악하지 못할 수 있음 |
| ==퓨샷 (Few-shot)== | 예시를 1~3개 보여주고 "이런 식으로 해줘" | AI가 예시의 스타일과 톤을 따라하므로 원하는 결과에 더 가까워짐 |

> 어떤 게 더 좋은 건 아니다 — 상황에 따라 골라 쓰면 된다.

### 제로샷 예시

```prompt
오늘 급식 메뉴를 맛집 리뷰처럼 써줘
```

### 퓨샷 예시

```prompt
아래 예시처럼 오늘 급식 메뉴를 리뷰해줘.
예시: "오늘의 돈까스는 겉바속촉! 소스가 짭짤달콤해서 밥도둑입니다. 별점 4.5/5"

오늘 급식 메뉴: [직접 입력]
```

## 🔄 나쁜 프롬프트 vs 좋은 프롬프트 비교

### 비교 예시 1 — 동아리 포스터

| 구분 | 프롬프트 |
|------|----------|
| 나쁜 프롬프트 | "포스터 만들어줘" |
| 좋은 프롬프트 | 아래 참고 |

```prompt
너는 그래픽 디자이너야.
우리 학교 코딩 동아리 신입부원 모집 포스터를 HTML로 만들어줘.
대상은 고1~고2 학생이고, 밝고 재미있는 느낌으로 해줘.
동아리 이름은 'Code Vibes', 활동 내용은 바이브 코딩으로 앱 만들기.
지원 마감은 4월 30일이야.
```

### 비교 예시 2 — D-day 웹페이지

| 구분 | 프롬프트 |
|------|----------|
| 나쁜 프롬프트 | "웹사이트 만들어줘" |
| 좋은 프롬프트 | 아래 참고 |

```prompt
고등학생이 사용할 시험 D-day 카운트다운 웹페이지를 만들어줘.
HTML, CSS, JavaScript를 하나의 파일에 작성하고,
시험 이름과 날짜를 입력하면 남은 일수를 큰 글씨로 보여줘.
배경은 깔끔한 하얀색, 폰트는 귀여운 느낌으로.
```

> ==핵심: 구체적일수록 AI가 더 정확하게 알아듣는다!==

## 🛠️ 실습 — 비포&애프터 챌린지

같은 주제로 두 번 AI에게 부탁해본다. 첫 번째는 일부러 대충, 두 번째는 오늘 배운 기법을 총동원해서!

### 실습 진행 순서

1. 아래 미션 중 하나를 선택한다.
2. **1차 시도**: 짧고 두루뭉실하게 프롬프트를 입력하고 결과를 확인한다.
3. **2차 시도**: 역할 + 목표 + 맥락 + 형식을 모두 포함해서 다시 요청하고 결과를 비교한다.
4. 아래 비교표에 결과를 기록한다.

### 미션 A — 학교 동아리 모집 포스터 HTML 만들기

- 1차 시도 (나쁜 프롬프트): `"동아리 포스터 만들어줘"`
- 2차 시도 (좋은 프롬프트): 역할 + 구체적 목표 + 맥락 + 형식을 모두 포함해서 재요청

### 미션 B — 오늘 급식 메뉴 맛집 리뷰

- 1차 시도: `"급식 리뷰 써줘"`
- 2차 시도: 오늘 실제 급식 메뉴를 적고, 퓨샷(예시 포함)으로 재요청

### 미션 C — 내 방 정리 체크리스트 웹페이지

- 1차 시도: `"체크리스트 만들어줘"`
- 2차 시도: 체크 항목, 디자인, 체크하면 줄이 그어지는 기능까지 구체적으로 요청

### 비교표 양식

| 구분 | 나쁜 프롬프트 | 좋은 프롬프트 | 결과 차이 한줄 정리 |
|------|--------------|--------------|-------------------|
| 미션 A | (적기) | (적기) | (적기) |
| 미션 B | (적기) | (적기) | (적기) |
| 미션 C | (적기) | (적기) | (적기) |

## 🏆 실습 — 자유 미션: 최고의 프롬프트 대회

### 규칙

1. 각자 원하는 주제를 자유롭게 정한다.
2. 오늘 배운 4가지 요소(==역할, 목표, 맥락, 형식==)를 모두 포함한 프롬프트를 작성한다.
3. Gemini에게 입력하여 결과물(HTML 웹페이지)을 받는다.
4. 결과물을 실행해서 브라우저에서 확인한다.

### 주제 예시

- "우리 반 시간표를 예쁘게 보여주는 웹페이지"
- "좋아하는 아이돌 프로필 카드"
- "오늘의 할 일 체크리스트"
- "친구에게 보내는 생일 축하 카드"
- "나만의 명언 모음 페이지"

## ✅ 오늘의 핵심 정리

1. ==프롬프트 엔지니어링== = AI에게 잘 말하는 기술
2. 좋은 프롬프트 4요소: ==역할 + 목표 + 맥락 + 형식==
3. ==제로샷== (예시 없이 바로 지시) vs ==퓨샷== (예시를 보여주고 지시) — 상황에 따라 선택
4. 구체적일수록 결과가 좋아진다
5. !!프롬프트를 잘 쓰는 연습 = 내 생각을 정리하는 연습!! — AI를 안 쓸 때도 평생 유용한 능력
