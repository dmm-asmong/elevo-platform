5회차: 앱의 얼굴을 만든다 — UI 디자인
═════════════════
수업 개요
* 주제: 기획서를 바탕으로 보기 좋고 사용하기 편한 UI 화면을 AI와 함께 완성하기
* 시간: 100분 (도입 10분 / 이론 10분 / 실습 70분 / 마무리 10분)
* 결과물: 나만의 웹앱 프론트엔드(UI 화면) 완성본
* 준비물: 크롬 브라우저, 구글 계정, 4회차에 만든 뼈대 코드, 디자인 참고 스크린샷
슬라이드 1 표지
* 제목: 5회차 — 앱의 얼굴을 만든다
* 부제: AI와 함께 예쁘고 쓰기 편한 화면 디자인하기
* 과정명: Gemini와 함께하는 바이브 코딩 입문
슬라이드 2 오늘 수업에서 할 것
* 좋은 UI 디자인이란 무엇인지 알아보기
* AI에게 디자인을 지시하는 프롬프트 기법 배우기
* 4회차에서 만든 뼈대를 바탕으로 앱의 전체 화면 디자인 완성
* 오늘의 결과물: 브라우저에서 열어보면 "와, 진짜 앱 같다!" 느낌이 나는 UI
슬라이드 3 도입 — 좋은 UI vs 나쁜 UI (강사용 교안)
* 소요시간: 10분
* 활동: 강사가 화면에 "못생긴 웹사이트" 예시 2~3개를 보여줌
* 예: 글꼴이 다 다르고, 색이 정신없고, 버튼 위치가 이상한 페이지
* 예: 글씨가 너무 작아서 못 읽는 페이지, 배경과 글자 색이 비슷해서 안 보이는 페이지
* 강사 멘트: "이런 사이트 보면 바로 나가죠? 앱이든 웹사이트든 '첫인상', 즉 디자인이 정말 중요해요. 그런데 좋은 소식! 디자인도 AI에게 시킬 수 있습니다."
* 그 다음: 잘 만든 웹사이트 예시 2~3개를 보여줌
* 예: 깔끔한 카드 레이아웃, 통일된 색상, 적절한 여백
* 강사 멘트: "차이가 느껴지죠? 비결은 통일감, 여백, 그리고 명확한 구조. 이걸 AI에게 말로 설명하면 됩니다."
* 과제 확인: "디자인 참고 스크린샷 가져오신 분?" → 2~3명이 화면에 띄워서 공유
슬라이드 4 도입 — 오늘의 출발점 확인 (강사용 교안)
* 강사 멘트: "자, 지난 시간에 기획서를 넣고 AI한테 뼈대를 받았죠? 그 코드를 브라우저에서 한번 열어보세요. 이게 오늘의 출발점이에요. 여기서 디자인을 입혀서 진짜 앱처럼 만들 겁니다."
* 학생들이 4회차 뼈대 코드 파일을 열어서 현재 상태를 확인
* 강사 유의사항: 코드를 잃어버린 학생은 기획서를 다시 AI에게 입력해서 빠르게 뼈대를 다시 받도록 안내. 5분 이내에 모든 학생이 출발점을 확보하도록 한다.
슬라이드 5 이론 — AI에게 디자인을 지시하는 3가지 기법 (이론 페이지)
* 소요시간: 10분
* 기법 1: 참고 대상 언급하기
* "인스타그램 스토리 같은 레이아웃으로 해줘"
* "네이버 메인 페이지처럼 깔끔하게"
* "카카오톡 채팅 화면 느낌으로"
* AI가 유명 서비스의 디자인 패턴을 학습하고 있으므로, 참고 대상을 언급하면 비슷한 느낌을 만들어줌
* 주의: 똑같이 베끼는 것이 아니라 "느낌"을 참고하는 것
* 기법 2: 제약 조건(Constraints) 주기
* "색상은 파란색과 흰색 2가지만 사용해줘"
* "모바일 화면(가로 400px 기준)에서도 잘 보이게 반응형으로 만들어줘"
* "다크 모드를 기본으로 해줘"
* 제약 조건을 주면 AI가 쓸데없이 복잡하게 만들지 않고, 일관된 결과를 만들어줌
* 쉽게 말하면: "이 안에서만 움직여" 라는 울타리를 쳐주는 것
* 기법 3: 반복 프롬프트(Iterative Prompting)
* 한 번에 완벽한 디자인을 기대하지 않는다
* 1차로 전체 틀을 받고 → "제목 크기를 더 키워줘" → "버튼 색을 빨간색으로" → "여백을 더 넓게" → 계속 대화하며 다듬기
* 비유: 미용실에서 머리 자르는 것과 같음. "좀 더 짧게", "앞머리만 다듬어주세요" 처럼 조금씩 조정
* 쉬운 풀이 박스:
* UI(User Interface, 사용자 인터페이스) = 사용자가 보고 만지는 화면. 버튼, 글씨, 색상, 배치 등 눈에 보이는 모든 것
* 반응형(Responsive) = 화면 크기에 따라 자동으로 레이아웃이 조정되는 것. PC에서도 폰에서도 잘 보이게
* 레이아웃(Layout) = 화면 안에서 요소들이 배치되는 구조. 위아래로? 좌우로? 카드 형태로?
* 여백(Padding/Margin) = 요소들 사이의 빈 공간. 여백이 충분해야 깔끔해 보임
* 다크 모드(Dark Mode) = 배경이 어둡고 글씨가 밝은 디자인. 눈이 편하고 세련된 느낌
슬라이드 6 이론 — 디자인 프롬프트 실전 예시 (이론 페이지)
* 나쁜 디자인 프롬프트:
* "예쁘게 해줘"
* → AI가 마음대로 색을 고르고 배치를 결정함. 내 취향과 다를 가능성 높음
* 좋은 디자인 프롬프트 예시:
이 웹앱의 디자인을 아래 조건으로 업그레이드해줘.
색상:
* 배경: 연한 크림색(#FFF8F0)
* 포인트 색상: 코랄 핑크(#FF6B6B)
* 텍스트: 진한 회색(#333333)
레이아웃:
* 카드 형태로 가운데 정렬
* 최대 가로 폭 480px (모바일 최적화)
* 요소 간 여백 충분히
글꼴:
* 제목은 크고 두꺼운 볼드체
* 본문은 읽기 편한 16px 이상
느낌:
* 귀엽고 따뜻한 느낌
* 둥근 모서리(border-radius: 16px)
* 카드에 부드러운 그림자 효과
* 핵심: 색상 코드를 몰라도 "코랄 핑크", "파스텔 블루"처럼 이름으로 써도 AI가 알아들음. 하지만 구체적일수록 정확도가 올라간다.
슬라이드 7 이론 → 실습 전환 (강사용 교안)
* 강사 멘트: "이론은 여기까지! 오늘은 실습 시간이 70분으로 넉넉해요. 왜냐하면 디자인은 해보면서 감을 잡아야 하거든요. 처음에 한 번에 완벽하게 나오지 않아도 괜찮아요. AI에게 계속 '이거 수정해줘', '저거 바꿔줘' 하면서 대화하는 과정 자체가 오늘의 핵심 실습이에요."
* AI 리터러시 포인트: "오늘 배울 것 중 가장 중요한 건 '제약 조건'이에요. AI에게 자유를 무한히 주면 오히려 산만한 결과가 나옵니다. '이 색만 써', '이 크기로 해'처럼 조건을 주면 더 좋은 결과가 나와요. 이건 실제 디자이너들도 쓰는 방법이에요."

* 제목: 실습 시간! (70분)
* 실습 1 (30분): 메인 화면 디자인 완성하기
* 쉬는 시간 (10분)
* 실습 2 (30분): 나머지 화면 + 모바일 반응형 + 자유 꾸미기
슬라이드 9 실습 1 — 메인 화면 디자인 (실습 페이지)
* 소요시간: 30분
* 목표: 앱의 첫 번째 화면(메인 화면)의 디자인을 완성한다
* 단계:
* Step 1: 4회차의 뼈대 코드를 Google AI Studio에 붙여넣기 (또는 대화를 이어가기)
* Step 2: 디자인 프롬프트 작성
* Step 3: 결과를 실행해서 확인
* Step 4: 마음에 안 드는 부분을 수정 프롬프트로 다듬기
* 프롬프트 작성 가이드 — 아래 빈칸을 채워서 나만의 디자인 프롬프트를 만든다:
이 웹앱의 디자인을 업그레이드해줘.
색상: 내가 원하는 색상 또는 느낌. 예: "파스텔 블루와 하얀색 조합"
레이아웃: 원하는 배치. 예: "카드 형태로 가운데 정렬", "전체 화면 사용"
글꼴 느낌: 예: "크고 둥글둥글한 느낌", "깔끔하고 모던한 느낌"
전체 분위기: 예: "귀여운", "게임 같은", "세련된", "따뜻한"
참고 서비스: 예: "인스타그램 느낌", "당근마켓 스타일"
추가 요청: 예: "이모지 많이 넣어줘", "둥근 모서리", "그림자 효과"
HTML, CSS, JavaScript를 하나의 파일에 합쳐서 작성해줘.
* 강사 유의사항: 학생이 색상이나 디자인 감각이 없다고 걱정하면 "느낌만 말해도 돼요. '귀여운', '깔끔한', '게임 같은'만 적어도 AI가 알아서 적절한 색과 폰트를 골라줍니다"라고 안심시킨다.
슬라이드 10 실습 1 — 반복 수정 연습 (실습 페이지)
* 결과가 나왔지만 마음에 안 드는 부분이 있을 때:
* 수정 프롬프트 예시 모음 (필요한 것 골라쓰기):
* 색상: "배경색을 좀 더 어두운 톤으로 바꿔줘"
* 크기: "제목 글씨를 더 크게, 본문 글씨는 조금 작게 해줘"
* 여백: "카드와 카드 사이 간격을 더 넓혀줘"
* 버튼: "버튼을 더 크게 만들고, 누르면 색이 변하는 효과를 넣어줘"
* 아이콘: "각 기능 옆에 적절한 이모지를 넣어줘"
* 레이아웃: "가로 배치를 세로 배치로 바꿔줘"
* 전체: "전체적으로 더 심플하게 정리해줘. 불필요한 요소를 줄여줘"
* 핵심 팁: 한 번에 여러 가지를 수정 요청하면 AI가 헷갈릴 수 있다. 한 번에 1~2가지씩 요청하고 확인하기!
* 강사가 돌아다니면서 학생별로 "지금 가장 아쉬운 부분이 뭐야?"라고 물어보고, 그 부분에 대한 수정 프롬프트를 함께 고민해준다.
슬라이드 11 쉬는 시간 (10분)
슬라이드 12 실습 2 — 나머지 화면 디자인 (실습 페이지)
* 소요시간: 30분 (전반 15분)
* 메인 화면이 완성되었으면, 기획서에 적은 나머지 화면도 디자인한다
* 프롬프트 예시:
메인 화면 디자인은 완성됐어. 이제 결과 화면도 같은 디자인 톤으로 만들어줘.
결과 화면에 포함할 것:
* 결과 제목 (큰 글씨)
* 결과 내용 (설명 텍스트)
* "다시 하기" 버튼
* "공유하기" 버튼
메인 화면과 같은 색상, 같은 폰트, 같은 카드 스타일을 유지해줘.
* 강사 유의사항: 화면이 1개뿐인 프로젝트(예: 운세 뽑기 같은 단일 페이지)인 경우, 이 시간에 세부 디자인을 더 다듬는 데 집중하게 한다.
슬라이드 13 실습 2 — 모바일 반응형 적용 (실습 페이지)
* 소요시간: 30분 (후반 15분)
* 모바일에서도 잘 보이게 만들기:
* 프롬프트 예시: "이 페이지를 모바일 화면(가로 400px 이하)에서도 잘 보이도록 반응형으로 만들어줘. 버튼이 너무 작지 않게, 글씨가 잘 읽히게 해줘."
* 확인 방법: 브라우저 창의 가로 폭을 좁혀보면서 레이아웃이 깨지는지 확인
* 또는 크롬 개발자도구(F12) → 모바일 미리보기 모드 사용 (강사가 시연)
* 시간이 남는 학생을 위한 추가 도전:
* 다크 모드 / 라이트 모드 토글 버튼 추가
* 페이지 로딩 시 간단한 애니메이션 넣기
* 스크롤 시 헤더가 고정되는 효과
* 버튼에 호버(마우스 올렸을 때) 효과 추가
* 쉬운 풀이 박스:
* 반응형 디자인(Responsive Design) = 화면 크기(PC, 태블릿, 스마트폰)에 따라 자동으로 레이아웃이 조정되는 디자인 방식
* 호버(Hover) 효과 = 마우스 커서를 요소 위에 올렸을 때 색이 바뀌거나 크기가 변하는 등의 시각 효과
슬라이드 14 마무리 — UI 갤러리 투어 (강사용 교안)
* 소요시간: 10분
* 활동: "UI 갤러리 투어" — 모든 학생이 자기 화면을 브라우저에 띄워놓고, 다 같이 돌아다니며 구경
* 강사 멘트: "자, 잠깐 일어나서 친구들 앱 구경하러 갑시다! 마음에 드는 디자인이 있으면 '이거 어떻게 했어?' 물어봐도 좋아요."
* 구경 후: 2~3명에게 "가장 마음에 든 친구의 디자인과 이유"를 발표하게 함
* 강사 멘트: "여러분이 각자 다른 기획서를 쓰고, 다른 프롬프트를 썼기 때문에 결과물이 전부 다르죠? AI는 같은 AI인데, 여러분의 기획과 지시가 다르니까 결과가 다른 겁니다. 다시 한번 강조하지만, AI는 도구이고 여러분이 창작자에요."
* 팁 공유: "친구의 결과물이 마음에 들었다면, 그 친구가 쓴 프롬프트를 물어보세요. 프롬프트를 참고하는 건 부끄러운 게 아니라 똑똑한 거예요!"
슬라이드 15 다음 시간 예고 & 과제
* 다음 시간 예고: "앱이 예뻐졌는데, 아직 버튼을 눌러도 반응이 없죠? 다음 시간에는 진짜 기능을 넣어서 살아 움직이는 앱으로 만들 거예요. 디버깅(에러 잡기)도 배웁니다!"
