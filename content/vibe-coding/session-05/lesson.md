# 5회차 — 앱의 얼굴을 만든다

> **오늘의 핵심 메시지:** ==디자인도 AI에게 시킬 수 있다. 단, 조건을 줄수록 결과가 좋아진다.==

## 🎯 오늘 배울 것

- 좋은 UI 디자인이란 무엇인지 이해하기
- AI에게 디자인을 지시하는 프롬프트 기법 3가지 배우기
- 4회차에서 만든 뼈대를 바탕으로 앱의 전체 화면 디자인 완성하기

오늘의 결과물: 브라우저에서 열어보면 "와, 진짜 앱 같다!" 느낌이 나는 UI

## 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| ==UI (User Interface, 사용자 인터페이스)== | 사용자가 보고 만지는 화면. 버튼, 글씨, 색상, 배치 등 눈에 보이는 모든 것 |
| ==반응형 (Responsive)== | 화면 크기(PC, 태블릿, 스마트폰)에 따라 자동으로 레이아웃이 조정되는 것 |
| ==레이아웃 (Layout)== | 화면 안에서 요소들이 배치되는 구조. 위아래로? 좌우로? 카드 형태로? |
| ==여백 (Padding/Margin)== | 요소들 사이의 빈 공간. 여백이 충분해야 깔끔해 보임 |
| ==다크 모드 (Dark Mode)== | 배경이 어둡고 글씨가 밝은 디자인. 눈이 편하고 세련된 느낌 |
| ==호버 (Hover) 효과== | 마우스 커서를 요소 위에 올렸을 때 색이 바뀌거나 크기가 변하는 등의 시각 효과 |
| ==반복 프롬프트 (Iterative Prompting)== | 한 번에 완벽한 결과를 기대하지 않고, 대화를 이어가며 조금씩 수정하는 방식 |

---

## 🎨 AI에게 디자인을 지시하는 3가지 기법

### 기법 1: 참고 대상 언급하기

AI는 유명 서비스의 디자인 패턴을 학습하고 있다. 참고 대상을 언급하면 비슷한 느낌을 만들어준다.

| 프롬프트 예시 | 효과 |
|--------------|------|
| "인스타그램 스토리 같은 레이아웃으로 해줘" | 세로형 풀스크린 카드 구성 |
| "네이버 메인 페이지처럼 깔끔하게" | 정보 밀도가 높고 정돈된 그리드 |
| "카카오톡 채팅 화면 느낌으로" | 말풍선 스타일, 연한 배경 |

> 주의: 똑같이 베끼는 것이 아니라 !!느낌!!을 참고하는 것이다.

### 기법 2: 제약 조건(Constraints) 주기

제약 조건을 주면 AI가 쓸데없이 복잡하게 만들지 않고, ==일관된 결과==를 만들어준다.

- "색상은 파란색과 흰색 2가지만 사용해줘"
- "모바일 화면(가로 400px 기준)에서도 잘 보이게 반응형으로 만들어줘"
- "다크 모드를 기본으로 해줘"

쉽게 말하면: =="이 안에서만 움직여"== 라는 울타리를 쳐주는 것.  
AI에게 자유를 무한히 주면 오히려 산만한 결과가 나온다. 조건을 줄수록 더 좋은 결과가 나온다.

### 기법 3: 반복 프롬프트(Iterative Prompting)

한 번에 완벽한 디자인을 기대하지 않는다.

1. 1차로 전체 틀을 받는다
2. "제목 크기를 더 키워줘"
3. "버튼 색을 빨간색으로"
4. "여백을 더 넓게"
5. 계속 대화하며 다듬는다

> 비유: 미용실에서 머리 자르는 것과 같다. "좀 더 짧게", "앞머리만 다듬어주세요"처럼 조금씩 조정하는 것.

## 💡 디자인 프롬프트 실전 예시

### 나쁜 프롬프트 vs 좋은 프롬프트

| 구분 | 예시 | 결과 |
|------|------|------|
| 나쁜 프롬프트 | "예쁘게 해줘" | AI가 마음대로 색을 고르고 배치를 결정함. 내 취향과 다를 가능성 높음 |
| 좋은 프롬프트 | 아래 예시처럼 조건을 구체적으로 명시 | 원하는 방향에 훨씬 가까운 결과 |

### 좋은 디자인 프롬프트 예시

```prompt
이 웹앱의 디자인을 아래 조건으로 업그레이드해줘.

색상:
- 배경: 연한 크림색(#FFF8F0)
- 포인트 색상: 코랄 핑크(#FF6B6B)
- 텍스트: 진한 회색(#333333)

레이아웃:
- 카드 형태로 가운데 정렬
- 최대 가로 폭 480px (모바일 최적화)
- 요소 간 여백 충분히

글꼴:
- 제목은 크고 두꺼운 볼드체
- 본문은 읽기 편한 16px 이상

느낌:
- 귀엽고 따뜻한 느낌
- 둥근 모서리(border-radius: 16px)
- 카드에 부드러운 그림자 효과
```

> 핵심: 색상 코드를 몰라도 "코랄 핑크", "파스텔 블루"처럼 이름으로 써도 AI가 알아들음. 하지만 ==구체적일수록 정확도가 올라간다.==

## 🛠️ 실습 1 — 메인 화면 디자인 완성하기

### 실습 단계

1. 4회차의 뼈대 코드를 Google AI Studio에 붙여넣기 (또는 대화를 이어가기)
2. 아래 가이드를 참고해서 나만의 디자인 프롬프트 작성하기
3. 결과를 브라우저에서 실행해서 확인하기
4. 마음에 안 드는 부분을 수정 프롬프트로 다듬기

### 나만의 디자인 프롬프트 작성 가이드

아래 빈칸을 채워서 나만의 프롬프트를 만든다.

```prompt
이 웹앱의 디자인을 업그레이드해줘.

색상: [원하는 색상 또는 느낌. 예: "파스텔 블루와 하얀색 조합"]
레이아웃: [원하는 배치. 예: "카드 형태로 가운데 정렬", "전체 화면 사용"]
글꼴 느낌: [예: "크고 둥글둥글한 느낌", "깔끔하고 모던한 느낌"]
전체 분위기: [예: "귀여운", "게임 같은", "세련된", "따뜻한"]
참고 서비스: [예: "인스타그램 느낌", "당근마켓 스타일"]
추가 요청: [예: "이모지 많이 넣어줘", "둥근 모서리", "그림자 효과"]

HTML, CSS, JavaScript를 하나의 파일에 합쳐서 작성해줘.
```

### 반복 수정 프롬프트 예시 모음

결과가 나왔지만 마음에 안 드는 부분이 있을 때, 필요한 것을 골라 쓴다.

| 수정 항목 | 프롬프트 예시 |
|-----------|--------------|
| 색상 | "배경색을 좀 더 어두운 톤으로 바꿔줘" |
| 크기 | "제목 글씨를 더 크게, 본문 글씨는 조금 작게 해줘" |
| 여백 | "카드와 카드 사이 간격을 더 넓혀줘" |
| 버튼 | "버튼을 더 크게 만들고, 누르면 색이 변하는 효과를 넣어줘" |
| 아이콘 | "각 기능 옆에 적절한 이모지를 넣어줘" |
| 레이아웃 | "가로 배치를 세로 배치로 바꿔줘" |
| 전체 정리 | "전체적으로 더 심플하게 정리해줘. 불필요한 요소를 줄여줘" |

> 핵심 팁: ==한 번에 1~2가지씩 요청==하고 확인한다. 한 번에 여러 가지를 수정 요청하면 AI가 헷갈릴 수 있다.

## 📱 실습 2 — 나머지 화면 + 모바일 반응형

### 나머지 화면 디자인하기

메인 화면이 완성되었으면, 기획서에 적은 나머지 화면도 같은 디자인 톤으로 만든다.

```prompt
메인 화면 디자인은 완성됐어. 이제 결과 화면도 같은 디자인 톤으로 만들어줘.

결과 화면에 포함할 것:
- 결과 제목 (큰 글씨)
- 결과 내용 (설명 텍스트)
- "다시 하기" 버튼
- "공유하기" 버튼

메인 화면과 같은 색상, 같은 폰트, 같은 카드 스타일을 유지해줘.
```

### 모바일 반응형 적용하기

모바일에서도 잘 보이게 만들기:

```prompt
이 페이지를 모바일 화면(가로 400px 이하)에서도 잘 보이도록 반응형으로 만들어줘.
버튼이 너무 작지 않게, 글씨가 잘 읽히게 해줘.
```

확인 방법:
1. 브라우저 창의 가로 폭을 좁혀보면서 레이아웃이 깨지는지 확인
2. 크롬 개발자도구(F12) → 모바일 미리보기 모드 사용

### 추가 도전 (시간이 남는 경우)

| 도전 과제 | 난이도 |
|-----------|--------|
| 다크 모드 / 라이트 모드 토글 버튼 추가 | ★★☆ |
| 페이지 로딩 시 간단한 애니메이션 넣기 | ★★☆ |
| 스크롤 시 헤더가 고정되는 효과 | ★★★ |
| 버튼에 호버(마우스 올렸을 때) 효과 추가 | ★☆☆ |

## ✅ 오늘의 핵심 정리

1. ==좋은 UI의 비결==은 통일감, 여백, 명확한 구조다.
2. AI 디자인 지시의 3가지 기법: !!참고 대상 언급하기!! / !!제약 조건 주기!! / !!반복 프롬프트!!
3. 제약 조건을 줄수록 AI가 일관된 결과를 만들어낸다.
4. 한 번에 완벽하지 않아도 된다. 계속 대화하며 다듬는 것이 핵심이다.
5. ==AI는 도구이고 여러분이 창작자다.== 같은 AI에게 같은 기획을 줘도 여러분의 프롬프트에 따라 결과가 달라진다.
