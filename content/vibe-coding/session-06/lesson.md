# 6회차 — 생명을 불어넣자: 기능 구현 & 디버깅

> **오늘의 핵심 메시지:** ==버튼이 진짜 작동한다!== 예쁜 화면에 실제 동작하는 기능을 AI와 함께 추가하고, 에러가 나면 AI로 해결한다.

## 🧠 웹앱의 3가지 구성 요소

지난 회차까지 HTML과 CSS로 앱의 외형을 완성했다. 오늘은 세 번째 요소인 ==JavaScript==를 다룬다.

| 구성 요소 | 역할 | 비유 |
|-----------|------|------|
| HTML | 화면에 무엇이 있는지 (제목, 버튼, 입력창 등) | 뼈대 |
| CSS | 어떻게 보이는지 (색상, 크기, 배치 등) | 옷 |
| JavaScript | 어떻게 동작하는지 (버튼을 누르면 뭐가 일어나는지) | 뇌 |

지금 앱은 겉모습은 있지만 뇌가 없는 상태, 즉 ==마네킹== 같은 상태다. 오늘은 여기에 뇌를 넣어서 살아 움직이게 만든다.

### 기능(로직)이란 무엇인가

기능의 핵심 패턴은 단 하나다:

> **"사용자가 ~하면 → ~이 일어난다"**

구체적인 예시:

- "버튼을 클릭하면 → 결과가 화면에 나타난다"
- "입력창에 글을 쓰고 엔터를 누르면 → 목록에 추가된다"
- "드롭다운에서 선택하면 → 선택한 값에 맞는 내용이 보인다"
- "날짜를 입력하면 → 오늘부터 그 날짜까지 남은 일수를 계산한다"

### 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| 로직(Logic) | 프로그램이 동작하는 규칙과 순서. "만약 A이면 B를 해라" 같은 것 |
| 함수(Function) | 특정 기능을 수행하는 코드 묶음. "이 버튼을 누르면 이 함수가 실행된다" |
| 이벤트(Event) | 사용자가 하는 행동. 클릭, 입력, 스크롤 등 |
| 프로토타입(Prototype) | 완성품 전 단계의 시제품. "일단 핵심 기능은 돌아가는 상태" |

## 🐛 디버깅 3단계

### 디버깅이란

==디버깅(Debugging)== 이란 코드에서 버그(오류)를 찾아서 고치는 것이다. 이름의 유래: 옛날 컴퓨터에 진짜 벌레(bug)가 들어가서 오작동한 것에서 유래했다.

!!바이브 코딩에서의 디버깅은 다르다.!! 코드를 직접 읽을 필요 없이, 에러 메시지를 AI에게 보여주면 AI가 고쳐준다.

### 에러가 나면 3단계로 해결한다

**1단계: 브라우저에서 에러 메시지 확인하기**

화면이 하얘지거나 버튼이 안 눌리면:
- 크롬에서 `F12` 키 누르기
- 오른쪽에 개발자 도구가 열림
- 상단에서 **"Console(콘솔)"** 탭 클릭
- ==빨간 글씨== 가 에러 메시지

콘솔을 여는 다른 방법:
- `Ctrl + Shift + J` (윈도우/리눅스)
- 페이지 아무 곳에서 마우스 오른쪽 버튼 클릭 → "검사" → Console 탭

콘솔 글씨 색깔 의미:

| 색깔 | 의미 |
|------|------|
| 빨간색 | 에러 — 이걸 복사해서 AI에게 보여준다 |
| 노란색 | 경고 — 심각하진 않지만 참고 |
| 흰색/회색 | 일반 정보 — 무시해도 됨 |

**2단계: 에러 메시지를 통째로 복사하기**

빨간 글씨를 드래그해서 선택 → `Ctrl+C`로 복사

**3단계: AI에게 에러 메시지를 보여주고 수정 요청하기**

```prompt
이 코드를 실행했더니 아래 에러가 나왔어. 원인을 찾아서 수정해줘.

[에러 메시지 붙여넣기]
```

AI가 수정된 코드를 주면 → 다시 저장 → 다시 실행 → 확인

### 에러 상황별 대처 가이드

| 상황 | 대처 방법 |
|------|-----------|
| 화면이 아예 하얗게 나온다 | F12 → Console 탭 → 빨간 에러 메시지 복사 후 AI에게 전달 |
| 화면은 나오는데 버튼을 눌러도 반응 없음 | F12 → Console 탭 → 버튼을 다시 눌러서 에러 메시지 확인 후 AI에게 전달 |
| 기능은 되는데 디자인이 깨졌다 | AI에게 "기능 추가 후 디자인이 깨졌어. 기능은 유지하면서 원래대로 복구해줘" 요청 |
| 에러 메시지를 못 찾겠다 | AI에게 "이 코드에서 문제가 있는 것 같아. 코드를 검토해서 잠재적인 문제를 찾아서 수정해줘" 요청 |

> 핵심: ==에러 메시지를 직접 이해할 필요 없다!== 그냥 통째로 복사해서 AI에게 보여주면 된다.

### 핵심 마인드셋

- 에러는 실패가 아니라 ==AI와 대화할 새로운 주제가 생긴 것!==
- 에러 없이 한 번에 완벽하게 되는 경우가 오히려 드물다
- "에러 → 수정 → 확인 → 에러 → 수정 → 확인"을 반복하는 것이 정상적인 개발 과정
- 완벽주의를 버리자 — =="충분히 좋은(good enough)"== 상태면 OK. 나머지는 나중에 개선

### 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| 디버깅(Debugging) | 코드의 오류(버그)를 찾아서 고치는 과정 |
| 콘솔(Console) | 브라우저에 숨어있는 개발자 도구. 에러 메시지가 여기에 표시됨. F12 또는 Ctrl+Shift+J로 열 수 있음 |
| 에러 메시지(Error Message) | 코드에 문제가 있을 때 컴퓨터가 알려주는 경고문. 무슨 에러인지, 어디에서 발생했는지 알려줌 |
| 점진적 개발(Incremental Development) | 기능을 한꺼번에 다 만들지 않고, 하나씩 추가하며 확인하는 방식 |

## 🎯 기능 요청 프롬프트 전략

### 한 번에 하나씩!

| 나쁜 예 | 좋은 예 |
|---------|---------|
| "모든 기능 다 넣어줘" | "먼저 기능 1만 구현해줘" → 확인 → "잘 되면 기능 2 추가해줘" → 확인 |

코드가 길어질수록 에러 가능성이 높아진다. ==점진적 개발(Incremental Development)== 로 하나씩 쌓아가는 것이 훨씬 안전하다.

### 기능 요청 기본 프롬프트 패턴

```prompt
지금 이 웹앱 코드에 아래 기능을 추가해줘.

기능: 사용자가 ~하면 → ~이 일어난다

조건:
- 기존 디자인(색상, 레이아웃, 폰트)은 절대 바꾸지 마
- 기존에 동작하던 기능도 깨뜨리지 마
- HTML, CSS, JavaScript를 하나의 파일에 유지해줘
```

> "기존 것을 건드리지 마"라는 조건이 매우 중요하다! AI에게 기능 추가를 요청하면 가끔 기존 디자인이나 다른 기능을 바꿔버리는 경우가 있다. "기존 코드는 유지하고, ~만 추가해줘"라고 명시하면 이 문제를 줄일 수 있다.

## ✨ 실습 2 — 추가 기능 & 마무리 다듬기

### 추가 기능 아이디어

핵심 기능이 동작하면, 재미있는 추가 기능에도 도전해보자. 원하는 것을 골라서 AI에게 요청한다.

| 추가 기능 | 프롬프트 예시 |
|-----------|---------------|
| 다시하기/초기화 버튼 | "결과 화면에서 '다시하기' 버튼을 누르면 처음 화면으로 돌아가게 해줘" |
| 결과 복사 기능 | "결과를 텍스트로 복사할 수 있는 '복사하기' 버튼을 추가해줘" |
| 진동/흔들림 애니메이션 | "결과가 나올 때 화면이 살짝 흔들리는 애니메이션을 넣어줘" |
| 다크모드 토글 | "오른쪽 상단에 해/달 아이콘 토글을 넣어서 다크 모드와 라이트 모드를 전환할 수 있게 해줘" |
| 사용 횟수 카운터 | "지금까지 몇 번 사용했는지 횟수를 화면에 표시해줘" |
| 로컬 저장 | "입력한 데이터가 브라우저를 닫아도 유지되게 localStorage에 저장해줘" |

### 전체 동작 테스트 체크리스트

핵심 기능을 넣은 후, 처음부터 끝까지 직접 사용해보며 확인한다.

- [ ] 앱을 처음 열었을 때 메인 화면이 정상으로 나타나는가?
- [ ] 핵심 기능 1이 동작하는가? (버튼 클릭 → 결과 표시)
- [ ] 핵심 기능 2가 동작하는가? (해당되면)
- [ ] 다시하기/초기화가 잘 되는가?
- [ ] 이상한 값을 넣었을 때 (아무것도 안 넣고 버튼 클릭 등) 에러가 나지 않는가?
- [ ] 모바일 크기에서도 화면이 깨지지 않는가?

테스트 중 문제를 발견하면 AI에게 설명한다:

```prompt
아무것도 선택 안 하고 버튼을 누르면 에러가 나.
아무것도 선택하지 않으면 "먼저 선택해주세요"라는 안내 메시지가 뜨도록 수정해줘.
```

> 실제 앱 개발에서도 '테스트' 과정이 반드시 필요하다. 만든 사람은 '이렇게 쓰겠지'라고 생각하지만, 사용자는 예상 못한 방식으로 쓰기 때문에 "아무것도 안 넣고 버튼 누르기", "이상한 값 넣어보기" 같은 테스트가 중요하다.

## ✅ 오늘의 핵심 정리

1. 웹앱의 뇌는 ==JavaScript==. "사용자가 ~하면 → ~이 일어난다" 패턴으로 기능을 정의한다.
2. 기능 요청은 ==한 번에 하나씩==. 기존 코드를 유지하라는 조건을 반드시 포함한다.
3. 에러가 나면 당황하지 말고 ==3단계== 를 따른다: F12로 에러 확인 → 복사 → AI에게 전달.
4. 에러는 실패가 아니라 ==AI와 대화할 새로운 주제==. 반복하는 것이 정상적인 개발 과정이다.
5. 핵심 기능이 동작하면 ==전체 동작 테스트==로 빈틈을 찾아 마무리한다.
