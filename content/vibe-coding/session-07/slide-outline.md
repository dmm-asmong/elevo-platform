슬라이드 6 실습 파트 1 — 배포란? (실습 페이지)
* 소요시간: 10분
* 배포(Deploy)란?
* 지금까지 내 컴퓨터에서만 열리는 .html 파일을 인터넷에 올려서, 누구나 링크(URL)를 통해 접속할 수 있게 만드는 것
* 비유: 집에서 혼자 보던 그림을 갤러리에 전시하는 것!
* 배포를 하면 → 친구에게 링크를 보내면 → 친구가 폰이나 컴퓨터에서 바로 내 앱을 써볼 수 있음
* 쉬운 풀이 박스:
* 배포(Deploy) = 만든 앱을 인터넷에 올려서 누구나 접속할 수 있게 하는 것
* 호스팅(Hosting) = 웹페이지 파일을 인터넷 서버에 올려두는 것. 서버가 24시간 켜져있으니 언제든 접속 가능
* URL = 인터넷 주소. 예: https://내이름.netlify.app
슬라이드 7 실습 파트 1 — 무료 배포 따라하기 (실습 페이지)
* 방법 A: Netlify Drop (가장 쉬움, 추천)
* 1단계: 브라우저에서 app.netlify.com/drop 접속
* 2단계: 내 .html 파일을 화면의 업로드 영역에 끌어다 놓기 (드래그 앤 드롭)
* 3단계: 몇 초 기다리면 자동으로 URL이 생성됨!
* 4단계: 생성된 URL을 복사해서 브라우저에 붙여넣기 → 내 앱이 인터넷에서 열리는지 확인
* 5단계: 이 URL을 친구에게 카카오톡으로 보내면 친구도 내 앱을 쓸 수 있음!
* 장점: 계정 없이도 가능, 30초면 끝
* 참고: 무료 계정은 일정 기간 후 사이트가 비활성화될 수 있음. 계속 유지하려면 Netlify 계정 가입(무료)
* 방법 B: GitHub Pages (계정 필요, 영구 무료)
* GitHub 계정이 있는 학생을 위한 대안
* 1단계: github.com에서 새 저장소(Repository) 만들기 (이름 예: my-app)
* 2단계: .html 파일을 index.html로 이름 바꾸기
* 3단계: 저장소에 파일 업로드
* 4단계: Settings → Pages → Branch를 main으로 선택 → Save
* 5단계: 몇 분 후 https://내아이디.github.io/my-app 으로 접속 가능
* 방법 C: Google AI Studio 내 배포 기능 (가능한 경우)
* Google AI Studio에서 직접 미리보기/배포 기능을 제공하는 경우 이를 활용
* 강사가 사전에 확인하여 가능하면 이 방법을 우선 안내
* 강사 유의사항: 모든 학생이 최소한 Netlify Drop 방법은 성공하도록 돕는다. 인터넷 속도가 느리거나 문제가 생기는 학생은 강사가 옆에서 도와준다. 이 과정에서 시간이 오래 걸리면 발표 시간을 살짝 줄여도 OK.

슬라이드 11 이론 — 환각 현상 (이론 페이지)
* 환각(Hallucination)이란?
* AI가 마치 사실인 것처럼 그럴듯하게 말하지만, 실제로는 틀린 정보를 만들어내는 현상
* 예: "이 약은 감기에 효과가 있습니다"라고 AI가 말했지만 실제로는 검증되지 않은 정보
* 예: AI가 만든 코드가 겉보기에 멀쩡하지만, 특정 상황에서 오류가 나는 경우
* 왜 이런 일이? AI는 "가장 그럴듯한 다음 단어"를 예측해서 문장을 만드는 것이지, 진짜/거짓을 판단하는 것이 아니기 때문
* 우리가 해야 할 것:
* AI의 답변을 무조건 믿지 말고, 특히 사실관계(숫자, 날짜, 이름 등)는 반드시 직접 확인하기
* 코드도 마찬가지: AI가 만든 코드가 진짜 잘 동작하는지 직접 테스트해봐야 함 (우리가 6회차에 한 것!)
* 쉬운 풀이 박스:
* 환각(Hallucination) = AI가 사실이 아닌 내용을 마치 사실처럼 그럴듯하게 생성하는 현상. AI는 거짓말을 "의도"하는 게 아니라, 그냥 확률적으로 그럴듯한 문장을 만들다 보니 발생하는 것
슬라이드 12 이론 — 보안과 개인정보 (이론 페이지)
* AI가 만든 코드의 보안 주의사항:
* 비밀번호, 개인정보(이름, 전화번호, 주소 등)를 코드에 직접 넣으면 안 됨
* 예: 코드 안에 password = "1234" 같은 걸 넣으면 누구나 볼 수 있음
* 배포한 웹앱의 코드는 누구나 F12를 눌러서 볼 수 있다는 것을 기억!
* AI에게 개인정보를 입력할 때도 주의
* 프롬프트에 친구의 실명, 전화번호, 주소 등을 넣지 않는 것이 좋음
* AI 서비스에 입력한 내용이 학습 데이터로 사용될 수 있음
* 우리가 해야 할 것:
* 앱에 민감한 정보를 넣지 않기
* AI에게 보내는 프롬프트에도 개인정보를 최소화하기
* "이 정보를 다른 사람이 본다면?" 항상 생각하기
슬라이드 13 이론 — 편향성과 저작권 (이론 페이지)
* AI의 편향성(Bias):
* AI는 학습한 데이터에 있는 편견을 그대로 반영할 수 있음
* 예: 특정 성별, 인종, 문화에 대한 고정관념이 결과에 나타날 수 있음
* 예: "CEO의 이미지를 그려줘"라고 하면 특정 성별/인종만 나올 수 있음
* AI가 만든 결과에 편향이 있는지 주의 깊게 살펴보는 자세가 필요
* 저작권:
* AI가 만든 코드/디자인의 저작권은 아직 법적으로 완전히 정리되지 않은 영역
* AI가 만든 결과물이 다른 사람의 작품과 너무 비슷하지 않은지 확인할 필요 있음
* 바이브 코딩으로 만든 앱을 상업적으로 사용하려면 이 부분을 더 공부해야 함
* 학교 과제나 개인 프로젝트 수준에서는 크게 걱정하지 않아도 되지만, "이건 AI가 도와줬다"는 것을 밝히는 것이 올바른 태도
* 쉬운 풀이 박스:
* 편향(Bias) = AI가 특정 방향으로 치우친 결과를 내는 것. 학습 데이터에 편견이 있으면 AI도 편견을 가지게 됨
* 저작권(Copyright) = 창작물에 대한 법적 권리. "내가 만든 것"을 다른 사람이 함부로 쓸 수 없게 보호하는 것
슬라이드 14 이론 — 오늘의 핵심 메시지 (이론 페이지)
* AI 시대의 현명한 사용자가 되는 5가지 원칙:
1. 확인하기: AI의 답변을 무조건 믿지 말고, 중요한 정보는 직접 확인한다
2. 보호하기: 개인정보와 민감한 데이터를 AI에게 함부로 주지 않는다
3. 의심하기: AI의 결과에 편향이나 오류가 없는지 비판적으로 살펴본다
4. 밝히기: AI의 도움을 받았다면 솔직하게 밝히는 것이 올바른 태도이다
5. 결정하기: 최종 판단과 책임은 항상 사람(나)에게 있다
* 강사 멘트: "AI는 여러분의 능력을 10배로 키워주는 도구예요. 하지만 도구는 도구일 뿐, 어디로 갈지 방향을 정하는 건 여러분이에요. 오늘 이 5가지만 기억해주세요."

* 발표 순서: 사전에 정한 순서 또는 자원자 순
* 강사 역할:

* 발표가 끝나면 한마디 코멘트: "와, OO 기능이 인상적이었어요!", "프롬프트를 정말 잘 쓰셨네요!"
* 학생들에게 박수를 유도
* 질문이 안 나오면 강사가 먼저 질문: "이 기능을 만들 때 프롬프트를 몇 번이나 수정했어요?", "가장 심각했던 에러는 뭐였어요?"
* 발표 분위기 만들기:
* 비판이나 평가가 아니라 "자랑과 축하"의 시간임을 강조
* "코드를 잘 짰느냐"가 아니라 "아이디어를 실현했느냐"에 초점
* 모든 발표 후 박수!
* 강사 유의사항:
* 학생 수가 많으면 (10명 이상) 2~3분으로 시간을 줄이거나, 조를 나눠서 동시에 진행
* 발표를 극도로 어려워하는 학생은 앱을 화면에 띄우고 강사가 대신 질문하는 "인터뷰" 형식으로 진행해도 OK
* 미완성인 학생도 "지금까지 완성된 부분"만 발표하면 됨. "완성도"가 아니라 "과정"이 중요함을 강조
