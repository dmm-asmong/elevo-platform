# 5회차 — Google Sheets 연동으로 온라인 랭킹·실시간 출결 시스템 만들기

> **오늘의 핵심 메시지:** ==내 브라우저 서랍을 온라인 저장소로 바꾼다==

---

## 🗄️ 왜 Google Sheets가 필요할까?

3일차에서 만든 게임의 최고 기록은 `localStorage`에 저장됐다. 하지만 `localStorage`는 **내 브라우저 안에만 있는 서랍**이다 — 시크릿 창으로 같은 게임을 열면 기록이 텅 비어 보인다. 서랍을 나누는 기준이 창이 아니라 **브라우저 프로필**이기 때문이다.

오늘은 그 서랍 바깥, ==브라우저가 꺼져도 남아 있고 다른 사람·다른 기기의 점수까지 한곳에 모이는== 저장소를 만든다. 서버 비용 0원으로, 이미 쓰고 있는 **Google Sheets를 내 웹앱의 데이터베이스**로 연결한다.

| | localStorage (3일차까지) | Google Sheets (오늘부터) |
|---|---|---|
| 접속 기기가 달라지면 | 기록이 안 보임 | 어느 기기로 접속해도 같은 기록이 보임 |
| 여러 사람이 쓰면 | 각자 자기 브라우저에만 쌓임 | 한 시트에 모두 누적됨 |
| 브라우저를 지우면 | 기록이 사라짐 | 시트에 그대로 남아 있음 |

### 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| **데이터 영속성** | 프로그램을 껐다 켜도 데이터가 남아있는 성질. 화이트보드가 아니라 종이 장부에 기록하는 것 |
| **서버리스(Serverless)** | 서버가 없다는 뜻이 아니라, 내가 직접 관리할 서버가 없다는 뜻. 인프라 관리를 구글이 전담한다 |

---

## 🍽️ 화면과 데이터는 원래 따로 산다

오늘 만드는 구조는 식당에 비유하면 이해가 쉽다.

- **홀(프론트엔드)** — 손님이 주문서를 작성하는 화면. 내 게임 HTML 파일이 여기에 해당한다. 손님이 나가면(창을 닫으면) 테이블은 깨끗이 치워진다 — 휘발성.
- **주방 장부(백엔드 DB)** — 모든 주문이 영구 보관되는 곳. Google Sheets가 여기에 해당한다. 홀이 문을 닫아도 장부는 안전하게 남는다.
- **그 사이를 오가는 창구** — 오늘 만들 **Apps Script 웹 앱 주소**다.

![식당 비유로 본 화면과 데이터의 분리 흐름](/images/vibe-coding-codex/session-05/개념-식당-데이터흐름.png)

### 🚪 doGet / doPost — 창구를 지키는 문지기 둘

Google Apps Script(GAS)는 원래 엑셀의 매크로처럼 스프레드시트 안 반복 업무를 자동화하는 도구였다. 여기에 구글이 **웹 앱 배포** 기능을 더하면서, 인터넷과 소통하는 백엔드 API 서버로 쓸 수 있게 됐다.

GAS 웹 앱이 되려면 반드시 `doGet` 또는 `doPost` 함수가 있어야 한다.

- **`doPost` (적어주는 문지기)** — 화면에서 점수를 보내면 시트 맨 아래에 한 줄을 적어 넣는다.
- **`doGet` (가져다주는 문지기)** — 화면에서 목록을 요청하면 시트 내용을 읽어 돌려준다.

은행 창구도 입금 창구와 출금 창구가 나뉘어 있는 것처럼, 적는 일(POST)과 읽는 일(GET)은 처음부터 다른 문으로 받는다.

![doPost와 doGet이 게임 화면과 시트 사이를 오가는 양방향 흐름](/images/vibe-coding-codex/session-05/개념-doPost-doGet-흐름.png)

> ==이 두 함수를 직접 타이핑하지 않는다.== 실습에서 Codex가 만들어준다. 지금 기억할 건 문법이 아니라 **"문이 두 개다 — 하나는 적고, 하나는 읽는다"** 이 한 줄이다.

### 📖 용어 정리

| 용어 | AI에게 요청할 때 쓰는 말 | 쉬운 풀이 |
|------|------|-----------|
| **doPost / doGet** | "doPost랑 doGet 둘 다 만들어줘" | 웹 요청을 받는 문지기 함수. POST는 저장, GET은 조회 |
| **배달형 전송(fetch)** | "fetch로 보내줘" | 화면을 새로고침하지 않고 뒤에서 조용히 데이터를 주고받는 방식 |
| **버튼 잠금** | "전송 중엔 버튼 비활성화해줘" | 전송 중 버튼을 잠가 같은 데이터가 중복 저장되는 걸 막는 안전장치 |
| **웹 앱 URL** | "이 주소로 보내줘" | 배포 완료 시 발급되는 고유 주소(`.../exec`). 이 주소가 곧 나의 API 창구 |

## 🚀 실습 1 — 내 게임에 온라인 랭킹 붙이기

### Step 1. 랭킹 시트 만들기

1. 구글 드라이브에서 **새로 만들기 → Google 스프레드시트**.
2. 파일 이름을 `게임랭킹_DB`로 바꾼다.
3. 1행에 `일시 / 닉네임 / 기록 / 비고`를 직접 타이핑한다.

> 온라인에 올라가는 데이터에는 필요한 것만 담는 게 원칙이다. 랭킹에 실명은 필요 없으므로 닉네임만 받는다 — 이것이 오늘 배울 **개인정보 최소 수집**의 첫 번째 실물 예시다.

### Step 2. Codex에게 백엔드 코드 요청하기

시트 상단 메뉴에서 **확장 프로그램 → Apps Script**를 열고, 아래 프롬프트를 전송한다.

```prompt
방금 만든 게임랭킹_DB 시트에 붙일 Apps Script 코드를 만들어 줘.
[시트 구조] A열 일시 / B열 닉네임 / C열 기록 / D열 비고
1. 닉네임과 기록이 전달되면 시트 맨 아래에 새 줄로 추가하고, 일시는 한국 시간으로 자동으로 채워 줘.
2. 화면에서 목록을 요청하면, 시트에 쌓인 기록 전체를 돌려줘.
3. 순위 정렬은 이 코드에서 하지 마. 순위 판정은 화면 쪽에서 할 거야.
4. 확장 프로그램 > Apps Script에 붙여넣을 Code.gs 전체 코드로 완성해 줘.
```

> ==프롬프트에 문법 용어가 하나도 없다는 점을 눈여겨보자.== `appendRow`나 `ContentService` 같은 말을 몰라도 "무엇을 어떻게 동작시키고 싶은지"만 정확히 쓰면 AI가 문법을 채운다. "이건 하지 마"를 명시하는 것도 프롬프트의 일부다.

받은 코드를 편집기 기존 내용을 **전부 지우고** 붙여넣은 뒤 `Ctrl+S`로 저장한다. 저장 후 `function doPost`와 `function doGet`, 그리고 `appendRow`라는 단어가 보이는지 확인한다 — 이게 여러분이 만든 백엔드 서버의 전부다. 나머지는 구글이 처리한다.

### Step 3. 웹 앱으로 배포하고 권한 승인하기

![Apps Script 배포 메뉴에서 새 배포를 선택하는 화면](/images/vibe-coding-codex/session-05/gas_06.png)

1. 우측 상단 **배포 → 새 배포** 클릭.
2. 유형 선택에서 **웹 앱**을 고른다.

![새 배포 창의 유형 선택 메뉴에서 웹 앱을 고르는 화면](/images/vibe-coding-codex/session-05/gas_07.png)

3. 설정을 아래처럼 맞춘다.

| 항목 | 설정값 | 이유 |
|---|---|---|
| 다음 사용자 권한으로 실행 | **나** | 내 시트에 쓰는 권한으로 동작해야 함 |
| 액세스 권한이 있는 사용자 | **모든 사용자** | "나"로 두면 나 말고는 아무도 점수를 못 보냄 |

![웹 앱 배포 설정에서 실행 사용자와 액세스 권한을 지정하는 화면](/images/vibe-coding-codex/session-05/gas_08.png)

4. **배포** 클릭 → 권한 승인 화면이 뜬다.

**"Google에서 확인되지 않은 앱" 경고**가 뜨더라도 당황할 필요 없다. 해킹이 아니라 구글이 "이 스크립트가 진짜 내 것이 맞는지" 확인하는 정상 절차다.

1. `권한 검토` 클릭 → 내 구글 계정 선택
2. 좌측 하단 **고급(Advanced)** 클릭

![Google hasn't verified this app 경고 화면에서 Advanced를 선택하는 화면](/images/vibe-coding-codex/session-05/gas_010.png)

3. **`[프로젝트 이름](으)로 이동(안전하지 않음)`** 클릭 → **허용(Allow)** 클릭

> "안전하지 않음"은 **구글이 검수하지 않은 앱**이라는 뜻이다. 방금 직접 만든 것이니 당연히 검수를 안 받았다. 내가 만든 걸 나에게 허용하는 것뿐이다.

5. 배포 완료 화면의 웹 앱 URL(`https://script.google.com/macros/s/.../exec`)을 복사해 메모장에 저장한다.
6. URL 끝이 반드시 **`/exec`**인지 확인한다 (`/dev`는 편집자 전용 테스트 주소).

### Step 4. 창구가 살아있는지 확인하기

복사한 `/exec` 주소를 브라우저 주소창에 붙여넣고 엔터를 친다. 화면에 이런 글자가 뜬다.

```json
{"result":"success","rows":[]}
```

이 화면이 "안 뜬다"고 느껴진다면, 원래 화면이 아니기 때문이다. 방금 만든 건 화면이 아니라 **데이터를 주고받는 창구**다. 식당 비유로 치면 홀이 아니라 주방으로 통하는 배식구를 들여다본 것이고, 아직 아무것도 없다(`rows:[]`)는 뜻이다. ==이 글자가 보이면 성공한 것이다.==

### Step 5. 내 게임에 온라인 랭킹 연결하기

먼저 AI가 내 게임 파일을 읽고 되묻게 한다. 3일차 게임은 스타터 4종 중 자율 선택이었으므로 기록 단위(ms·점·회)와 "좋은 기록의 방향"이 학생마다 다르기 때문이다.

```prompt
3일차에 만든 게임 파일을 열어봐.
이 게임의 기록을 아까 만든 게임랭킹_DB 시트에 모아서 온라인 랭킹을 만들고 싶어.
(시트 열: 일시 · 닉네임 · 기록 · 비고)
아직 파일은 고치지 말고, 시작하기 전에 두 가지만 먼저 물어봐 줘.
1. 내 게임의 어떤 값이 '기록' 칸에 들어가야 하는지
2. 그 값은 클수록 좋은 기록인지, 작을수록 좋은 기록인지
```

AI가 확인한 답을 바탕으로 아래 프롬프트를 전송한다.

```prompt
방금 배포한 Apps Script 웹앱 주소는 (복사한 URL)입니다.

내 게임에 온라인 랭킹 등록 기능을 추가해 줘.

1. 게임이 끝나서 기록이 나오면, 닉네임을 입력받는 칸과
   [랭킹 등록] 버튼이 활성화되게 해 줘.
2. 버튼을 누르면 화면이 새로고침되지 않은 채로,
   fetch로 위 주소에 닉네임과 기록을 전송해 줘.
3. 전송 중에는 버튼을 비활성화하고 "전송 중..." 표시를 보여줘.
4. 지금 있는 localStorage 최고기록 기능은 지우지 말고 그대로 둬.
   내 브라우저 서랍과 온라인 랭킹은 둘 다 있어야 해.
5. 기존에 잘 작동하는 게임 로직과 디자인을 훼손하지 말고
   안전하게 반영해 줘.
```

> !!4번 줄을 지우지 말 것!! — 이 조건이 빠지면 AI가 `localStorage` 저장 로직을 시트 전송으로 대체해버릴 수 있다. 그러면 3일차에 만든 기능이 사라진다.

AI가 코드를 고치기 **전에** 보여주는 작업 계획에서 다음 세 가지를 확인한다.

1. 3일차에 만든 그 파일을 고치겠다고 하는가?
2. `localStorage` 기능을 지우겠다고 하지 않는가?
3. 시트 4열 구조 그대로인가?

게임을 열어 한 판 플레이하고 닉네임을 입력해 랭킹에 등록한 뒤, Google Sheets를 열어 **새 줄이 실제로 생겼는지** 확인한다. 화면의 "등록했습니다" 메시지가 아니라 **시트에 생긴 새 줄이 성공의 기준**이다.

## 🔁 실습 2 — 같은 5단계를 안내 없이 반복하기 (실시간 출결 시스템)

오전에 한 절차를 오후에는 소재만 바꿔서 스스로 해본다. **시트 → 코드 → 배포 → 주소 확인 → 화면 연결**, 같은 5단계다.

### Step 1. 출결용 시트 + Apps Script 배포

1. 새 스프레드시트를 만들고 이름을 `출석부_DB`로 바꾼다.
2. 1행 헤더: `일시 / 이름 / 휴대폰 뒷자리 / 비고`
3. 확장 프로그램 → Apps Script → Codex에게 코드 요청(위와 같은 방식, 열 이름만 바꿔서) → 붙여넣고 저장
4. 배포 → 새 배포 → 웹 앱 / 실행: 나 / 액세스: 모든 사용자 → 권한 승인 3단계
5. `/exec` 주소 복사 → 주소창에 붙여넣어 JSON이 뜨는지 확인

> ==오전에 만든 게임용 주소를 그대로 쓰면 안 된다.== 시트가 다르므로 배포도 새로 해야 한다.

### Step 2. Codex로 출결 화면 만들고 연결하기

```prompt
방금 배포한 웹앱 주소는 (복사한 URL)입니다.
[이름], [휴대폰 번호 뒷자리 4자리], [비고] 입력창과 [출석체크] 버튼이 있는
다크모드 attendance.html을 만들어줘.
[요구사항]
1. 버튼을 누르면 화면이 새로고침되지 않은 채로, fetch로 위 주소에 데이터를 전송해줘.
2. 전송 중에는 버튼을 비활성화하고 "전송 중..." 로딩 표시를 보여줘.
3. 성공 시 "출석체크 완료!" 축하 모달을 띄우고 입력창을 자동으로 초기화해줘.
4. DO NOT LEAVE PLACEHOLDERS — 전체 완성된 코드를 처음부터 끝까지 생략 없이 작성해줘.
```

완성 후 가상 데이터로 3건을 제출해 시트에 매번 새 행이 추가되는지 확인한다. ==실제 개인정보는 절대 입력하지 않는다.==

### 심화 — 관리자 실시간 조회 화면 (선택)

```prompt
하단에 "오늘의 출석 현황 보기" 버튼을 추가해줘.
버튼을 누르면 구글 시트의 doGet API를 호출해서,
최근 출석 명단을 시간 역순으로 예쁜 표로 보여줘.
```

## 🔐 보안 제1수칙 — 개인정보 최소 수집

오전 게임 랭킹 시트에는 닉네임과 점수만 들어갔다. 유출돼도 곤란할 게 없다. 반면 오후 출결 시트에는 이름과 휴대폰 번호 뒷자리가 들어간다 — 전체 번호가 아니어도 개인정보로 보고 주의해서 다뤄야 한다.

- **HTML 소스코드는 브라우저에서 `F12`를 누르면 전 세계 누구나 볼 수 있다.** 관리자 비밀번호나 민감한 개인정보를 자바스크립트 안에 하드코딩해서는 안 된다.
- **실습 중에는 반드시 가상 데이터만 입력한다.** `홍길동 / 5678` 같은 가짜 값을 쓰고, 실제 휴대폰 번호 전체·주민번호·실계좌는 절대 입력하지 않는다.
- **필요한 것만 받는다.** 오전에 닉네임만 받았던 것처럼, 실제로 쓸 항목이 아니면 애초에 받지 않는 것이 가장 확실한 보안이다.

### 📖 용어 정리

| 용어 | AI에게 요청할 때 쓰는 말 | 쉬운 풀이 |
|------|------|-----------|
| **비밀번호 하드코딩 금지** | "API 키는 코드에 직접 쓰지 마" | 비밀번호·키 값을 코드 안에 그대로 적어두는 것. `F12`로 누구나 볼 수 있어 절대 금지 |
| **개인정보 최소 수집** | "꼭 필요한 항목만 받게 해줘" | 안 받으면 유출될 일도 없다는 원칙 |

## 🌍 완성 — 내 폰으로 접속해서 글로벌 랭킹 확인하기

4일차에 만든 저장소(`본인프로젝트명-codex`) 폴더에 오늘 만든 두 파일을 옮긴다.

- 오전에 만든 게임 → `game.html`
- 오후에 만든 출결 앱 → `attendance.html`
- `index.html`은 건드리지 않는다.

```prompt
방금 추가한 game.html과 attendance.html을 커밋하고 푸시해 줘.
커밋 메시지는 "5일차 Google Sheets 연동 - 게임 온라인 랭킹, 출결 시스템"으로 해 줘.
```

Vercel이 자동 재배포되면, PC 화면에 `게임랭킹_DB` 시트를 띄워둔 채 **내 스마트폰**으로 `내주소/game.html`에 접속해 한 판 플레이하고 닉네임을 등록해본다. PC 화면의 시트에 폰에서 낸 점수가 뜨면, 서로 다른 두 기기의 기록이 한곳에 모인 것 — ==오늘 오락실 기계를 온라인 서비스로 바꾼 것==이다.

> **폰 접속 시 주의:** 주소는 카카오톡으로 보내지 말고 화면에 띄운 주소를 폰 브라우저에 직접 입력한다(카톡 인앱 브라우저는 동작이 다를 수 있다). 폰에서 구글 로그인을 요구하면 시크릿 모드로 접속한다. 점수가 시트에 안 뜨면 화면 메시지를 기다리지 말고 시트를 새로고침해본다.

## ✅ 오늘의 핵심 정리

1. **화면과 데이터는 분리되어 있다.** 프론트엔드(홀)는 휘발성이고, 백엔드 DB(주방 장부)는 영구 보관된다.
2. **doPost는 적고, doGet은 읽는다.** 문지기 두 개가 API 창구의 전부다.
3. **`/exec` 주소에 글자만 뜨면 성공이다.** 화면이 아니라 창구이기 때문이다.
4. **성공의 기준은 화면 메시지가 아니라 시트에 쌓인 데이터다.**
5. **개인정보는 최소한만 수집한다.** 필요한 것만 받는 것이 가장 확실한 보안이다.
