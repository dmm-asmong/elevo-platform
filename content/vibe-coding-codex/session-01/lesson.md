> **오늘의 핵심 메시지:** ==나는 타이핑하는 사람이 아니라, AI를 지휘하는 사람이다==

## 🚀 바이브코딩, 코드가 아니라 지휘다

### "가장 핫한 새 프로그래밍 언어는 영어다"

전 테슬라 AI 총괄이자 OpenAI 창립 멤버인 **안드레이 카파시(Andrej Karpathy)**는 이렇게 말했다.

> "가장 핫한 새로운 프로그래밍 언어는 바로 영어(자연어)다."

지난 수십 년간 소프트웨어 개발의 가장 큰 병목은 ==문법을 외우고 타이핑하는 것==이었다. 이제 그 일은 AI가 대신한다. 사람에게 남은 진짜 역할은 **어떤 문제를 풀지 정하고, AI에게 올바른 방향을 지시하는 지휘(Orchestration) 능력**이다.

오늘부터 이 과정에서는 문법이 아니라 **의도를 명확히 전달하는 법**을 배운다.

### 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| **바이브코딩** | 자연어로 AI에게 설명해서 코드를 완성하는 개발 방식 |
| **오케스트레이션** | 코드를 직접 치는 대신, AI에게 방향을 지시하고 결과를 검증하는 지휘 역할 |
| **Codex** | OpenAI가 만든 에이전트형 개발 도구. 내 컴퓨터의 지정된 폴더 안에서 파일을 직접 읽고 쓴다 |

## 🛠 ChatGPT Chat vs Work vs Codex

같은 ChatGPT Plus 안에서도 ==쓰는 목적에 따라 완전히 다른 도구==를 골라야 한다.

| 비교 항목 | ChatGPT Chat 💬 | ChatGPT Work 💼 | Codex 🛠️ |
|---|---|---|---|
| 역할 비유 | 전화 상담사 | 클라우드 업무 비서 | 내 컴퓨터에 상주하는 전담 개발자 |
| 작동 환경 | 브라우저 단발 대화 | 클라우드 프로젝트 공간 | 내 컴퓨터 로컬 폴더 |
| 파일 접근 | 1개씩 업로드 필요 | 연결된 문서 읽기 | 프로젝트 폴더 안 모든 파일을 직접 탐색 |
| 결과 반영 | 화면에 텍스트만 출력 → 사람이 복붙 | 문서·표 작성 | 실제 파일을 **직접 생성·수정** |
| 이럴 때 | 질문하고 개념 배울 때 | 반복 문서 정리 | !!실제 웹사이트·프로덕트를 만들 때!! |

오늘부터 우리가 쓰는 도구는 **Codex**다.

## 📁 왜 "프로젝트 폴더"를 먼저 정해야 할까

Codex를 켜기 전에 무조건 ==작업할 폴더부터 정하거나 만든다==. 여기에는 3가지 이유가 있다.

1. **맥락의 영구 보존** — 프로젝트 폴더를 지정해두면 새 대화를 열어도 폴더 안 파일 구조와 진행 상황이 그대로 유지된다.
2. **안전 격리(Sandbox)** — AI에게 컴퓨터 전체를 열어주는 대신, "이 폴더 안에서만 일해!"라고 안전한 작업 구역을 한정한다. 내 사진·문서·다운로드 폴더는 건드리지 못한다.
3. **파일 간 관계 파악** — 파일을 하나씩 복붙해서 올릴 필요 없이, AI가 폴더 안 여러 파일의 이름과 구조를 스스로 읽고 파악한다.

### 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| **컨텍스트 윈도우** | AI가 한 번에 기억할 수 있는 대화·정보의 크기. 정해진 크기의 화이트보드라고 생각하면 된다 |
| **컨텍스트 드리프트** | 대화가 너무 길어져 화이트보드가 꽉 차면, AI가 처음 규칙을 잊어버리는 현상 |

### Codex 필수 슬래시(`/`) 명령어 3종

| 명령어 | 기능 | 언제 쓸까 |
|---|---|---|
| `/status` | 현재 세션의 컨텍스트 사용량·모델 상태 확인 | 대화가 길어졌을 때 |
| `/permissions` | 파일 자동 수정·명령 실행에 대한 승인 모드 설정 | 실습 시작 전, 항상 먼저 |
| `/clear` | 현재 세션의 대화 기억을 완전히 초기화 | 대화가 꼬였을 때 |

> !!실습을 시작하기 전에는 항상 `/permissions`로 승인 모드가 "승인 후 실행"인지 먼저 확인한다.!! AI가 지시 없이 파일을 마음대로 옮기는 사고를 막아준다.

## 💬 2단계 소통 — Ask Mode → Code Mode

Codex와 안전하게 일하는 핵심 습관은 ==한 번에 실행시키지 않고 계획부터 확인하는 것==이다.

1. **Ask Mode (계획 먼저 보기):** "파일을 직접 옮기거나 삭제하지 마세요. 어떻게 할지 계획표를 먼저 보여주세요."
2. **Code Mode (검토 후 실행 승인):** 계획을 눈으로 확인한 뒤 "이 계획대로 실행해 주세요."

```prompt
이 폴더는 실습용 폴더입니다.
지금 파일을 절대 직접 옮기거나 삭제하지 마세요.
먼저 폴더 안 파일들을 모두 확인하고, 업무 효율을 극대화할 수 있는 분류 기준을 제안해 주세요.

출력 형식:
| 파일명 | 추정 내용 | 추천 폴더명 | 분류 이유 |
형태의 마크다운 표로 보여주세요.
```

제안된 표를 확인하고 마음에 안 드는 부분이 있으면 구체적으로 수정을 요청한다.

```prompt
수정된 계획표에 최종 동의합니다. 제안한 대로 실제 폴더들을 생성하고,
파일을 각각의 폴더 안으로 안전하게 이동시켜 주세요.
```

이 두 단계만 익혀도 ==AI가 내 컴퓨터에서 사고를 칠 걱정 없이== 안전하게 실습할 수 있다.

## 🍽 소프트웨어를 레스토랑으로 이해하기

웹앱은 아래 4가지 요소로 이루어진다.

- **프론트엔드 (홀 & 메뉴판)** — HTML(뼈대) + CSS(인테리어). 사용자가 보는 화면
- **API (웨이터)** — 데이터와 요청을 배달하는 통로
- **백엔드 (주방)** — JavaScript. 버튼을 눌렀을 때 실제 동작과 계산을 담당
- **데이터베이스 (식자재 창고)** — 데이터가 휘발되지 않고 영구 보관되는 곳

오늘은 이 중 프론트엔드와 백엔드(JavaScript)까지 다룬다. API와 데이터베이스는 이후 회차에서 만난다.

## 🎯 마스터 프롬프트 C-G-S-C 공식

막연하게 "예쁘게 만들어줘"라고 하면 결과가 들쭉날쭉하다. ==구체적인 4가지 요소를 채워 넣으면 결과가 확 좋아진다.==

| 공식 | 의미 | 질문 가이드 |
|---|---|---|
| **C**ontext | 맥락/정보 | 나는 누구이며, 어떤 정보가 들어가는가? |
| **G**oal | 목표 | 최종적으로 어떤 산출물을 원하는가? |
| **S**tyle | 스타일/디자인 | 어떤 시각적 느낌과 테마를 원하는가? |
| **C**onstraint | 핵심 제약 | 기술적으로 반드시 지켜야 할 규칙은? |

### 디펜시브 프롬프트 지시어 2가지

항상 아래 두 문구를 요청 끝에 붙이면 실수를 크게 줄일 수 있다.

- **`코드를 생략하지 말 것`** — "코드 중간에 `// 여기에 코드를 작성하세요` 같은 생략 표시를 남기지 말고, 처음부터 끝까지 완전한 전체 코드를 출력해줘."
- **`임의 수정 금지`** — "요청하지 않은 다른 파일이나 구조는 임의로 수정하지 마."

## 🎨 오늘의 결과물 — 인터랙티브 프로필 명함

### 마스터 프롬프트로 첫 웹앱 만들기

```prompt
너는 최고의 인터랙티브 웹 프론트엔드 디자이너이자 개발자야.
아래 정보를 바탕으로 나를 돋보이게 하는 멋진 [1인 비즈니스 프로필 명함 웹앱]을 만들어줘.

[Context - 프로필 정보]
- 이름: [ 내 이름 ]
- 한 줄 소개 / 직함: [ 예: AI 바이브코딩 크리에이터 ]
- 대표 전문 키워드 배지 3개: [ 예: #업무자동화, #생성형AI, #노코드웹앱 ]
- 대표 소개 문구: [ 한 문장으로 ]

[Goal - 구현 목표]
- 모바일과 PC 화면 모두에 완벽하게 대응하는 반응형 프로필 카드 레이아웃
- 상단에 아바타, 키워드 배지, 소개 문구가 깔끔하게 정렬된 모던 카드 UI

[Style - 디자인 감각]
- 배경: 다크 네이비/딥 퍼플 그라데이션
- 카드: 반투명 글래스모피즘 효과, 둥근 모서리, 마우스 오버 시 은은한 네온 글로우

[Constraint - 필수 기술 제약]
- 외부 파일 분리 없이, HTML/CSS/JavaScript를 반드시 단 하나의 'profile.html' 파일 안에 완전한 코드로 작성해줘.
- 코드 중간에 생략이나 주석 플레이스홀더를 절대 남기지 말고 전체 코드를 출력해줘.
- 한글이 깨지지 않도록 반드시 <meta charset="UTF-8"> 태그를 포함해줘.
```

Codex가 만들어준 코드를 저장한 뒤, 파일을 **크롬 브라우저 창으로 드래그 앤 드롭**하면 바로 화면에 뜬다.

### 저장 3대 수칙 (실수 1위 예방)

메모장으로 저장할 때는 ==파일 형식을 "모든 파일(*.*)"로 바꾸고, 인코딩은 UTF-8로 지정==해야 한다. 그렇지 않으면 `profile.html.txt`로 저장되어 브라우저로 열리지 않거나, 한글이 깨진다.

### 티키타카로 다듬기

처음 결과가 마음에 안 들면 계속 대화하며 고치면 된다. 모든 수정 요청 끝에는 **"코드를 생략하지 말고 전체를 다시 출력해줘"**를 붙인다.

```prompt
profile.html 하단에 [🔮 오늘의 비즈니스 운세 뽑기] 버튼을 추가해줘.
버튼을 클릭하면 성공/동기부여 명언 중 하나가 화면 중앙에 모달 팝업으로 떠오르고,
화면에 축하 폭죽(Confetti) 애니메이션이 함께 터지게 해줘.

[필수 제약]
절대 코드를 생략하지 말고, profile.html 전체 원본 코드를 완전하게 다시 출력해줘.
```

> !!새로고침(F5)을 해도 화면이 그대로면, `Ctrl + Shift + R`(강력 새로고침)을 눌러보자.!! 브라우저 캐시 때문에 예전 화면이 남아있는 경우가 많다.

## 🧑‍💻 에러가 났을 때 — F12 콘솔 복붙 디버깅

화면이 반응하지 않을 때 당황해서 코드를 직접 고치려 하지 말고, 아래 4단계를 따른다.

1. **증상 발견** — 버튼을 눌렀는데 반응이 없다
2. **F12로 개발자 도구 열기**
3. **Console 탭에서 빨간 에러 메시지 복사**
4. **Codex에 에러 원문을 그대로 붙여넣고 질문**

```prompt
[오류 보고 및 수정 요청]
웹페이지에서 '운세 뽑기' 버튼을 눌렀는데 반응이 없습니다.
브라우저 F12 개발자 도구 콘솔에 아래와 같은 빨간색 에러가 떴습니다.

[에러 메시지 원문]
(여기에 복사한 에러 메시지를 붙여넣기)

이 에러가 발생한 원인을 비개발자도 이해하기 쉬운 한국어로 먼저 설명해주고,
오류를 수정한 전체 완전한 코드를 다시 작성해줘.
```

==에러 메시지는 두려운 대상이 아니라 AI에게 주는 가장 정확한 단서==다.

## ✅ 오늘의 핵심 정리

1. **바이브코딩 = 지휘.** 문법을 외우는 게 아니라, 원하는 것을 명확히 전달하고 결과를 검증하는 것이 핵심 역량이다.
2. **Codex는 로컬 폴더에서 일하는 개발자.** 실습 전에는 항상 작업 폴더를 먼저 정하고, `/permissions`로 승인 모드를 확인한다.
3. **Ask Mode → Code Mode.** 계획을 먼저 확인하고 승인한 뒤에 실행을 지시하면 안전하다.
4. **C-G-S-C 공식**으로 구체적으로 요청할수록 결과물의 완성도가 올라간다.
5. **에러는 F12 콘솔에서 복사해 AI에게 그대로 붙여넣고 물어본다.**
