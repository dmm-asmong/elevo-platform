# 3회차 — 인터랙티브 웹앱 + localStorage 하이스코어

> **오늘의 핵심 메시지:** ==정적인 페이지를 넘어, 누르면 반응하고 기록이 남는 살아있는 웹앱을 만든다.==

---

## ⚡ 왜 게임으로 배우는가

게임은 소프트웨어의 3대 핵심 메커니즘을 압축해서 보여준다.

1. **입력** — 사용자의 클릭·터치에 반응한다.
2. **상태** — 현재 점수·시간을 기억한다.
3. **조건** — 성공·실패를 판정한다.

일반 업무 프로그램은 잘 작동하는지 눈으로 확인하기 어렵지만, 게임은 누르면 즉시 반응이 보이기 때문에 원리를 온몸으로 체감할 수 있다. 게임이 멈추거나 점수가 안 오를 때 에러를 잡는 훈련을 해두면, 어떤 비즈니스 웹앱을 만들어도 두렵지 않다.

### 3일차까지의 흐름

```
1일차: AI 지휘 루프    → Codex와 소통하고 결과를 검증하는 루프 확립
2일차: 정적 웹페이지   → HTML(뼈대) + CSS(디자인)로 소개 사이트 완성
3일차: 인터랙티브 웹   → JavaScript(즉각 반응) + localStorage(서랍 영구 보존)
```

## 🛡 AI를 지휘하는 2가지 안전벨트

### 1. 한 번에 다 시키지 않는다 — 점진적 빌드

"로그인, 랭킹, 난이도, 효과음 다 들어간 완벽한 게임 만들어줘"라고 한 번에 요청하면 AI가 수백 줄을 쏟아내다 코드끼리 충돌한다. 항상 3단계로 나눠 확장한다.

1. **기본 1판 MVP** — 화면 + 클릭 조작 + 기본 점수만 딱 돌아가는 가장 단순한 형태부터 만든다.
2. **1기능씩 추가** — 잘 도는 것을 확인한 뒤, 타이머나 난이도 등 원하는 기능을 하나씩만 요청한다.
3. **영구 저장 & 연출 안착** — 핵심 게임이 안정되면 그때 기록 저장과 신기록 연출을 붙인다.

### 2. 멈추면 무조건 콘솔 빨간 글씨 복붙 — 레이지 프롬프팅

**레이지 프롬프팅(lazy prompting)**은 에러가 났을 때 사람이 원인을 해석하지 않고, ==브라우저 콘솔에 뜬 에러 원문을 그대로 AI에게 붙여넣는== 방식이다. AI 연구자 앤드루 응(Andrew Ng)이 이름 붙인 용어로, 실제로 많은 개발자가 에러 메시지를 통째로 복사해 AI에게 넘기는 방식으로 디버깅한다.

AI는 내 코드 파일은 읽을 수 있지만, "내가 방금 무엇을 눌렀고 어디서 멈췄는지"는 파일에 적혀 있지 않다. 그 정보는 **실행하는 순간에만 생기고, 콘솔의 빨간 줄에 남는다.** 그래서 "버튼이 안 눌려요"라고만 말하면 AI는 짐작으로 고치다가 빗나가고, "버튼이 안 눌려요" 대신 ==빨간 에러 메시지 전체==를 그대로 전달하면 AI가 훨씬 정확하게 원인을 짚는다.

```
1. F12 (또는 Ctrl+Shift+J)로 개발자 도구 열기
2. Console 탭 클릭
3. 빨간 줄을 드래그해서 Ctrl+C
4. 그대로 AI에게 붙여넣기
```

### 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| **레이지 프롬프팅** | 에러 메시지를 요약하지 않고 원문 그대로 AI에게 전달하는 디버깅 방식 |
| **컨텍스트 오염** | 대화가 길어지며 AI가 이전의 잘못된 코드를 계속 반복하는 현상. `/clear`로 초기화한다 |

## 🎮 아이디어가 고민된다면 — 스타터 4종

자신만의 아이디어가 있다면 자유롭게 시작하고, 아이디어가 떠오르지 않으면 아래 중 하나를 골라 시작해도 된다.

| 스타터 | 핵심 재미 요소 | 기록 지표 |
|---|---|---|
| ⚡ 스피드 반응속도 테스트 | 화면이 바뀌는 순간 번개 클릭 → 밀리초(ms) 측정 | 반응시간(ms) — **작을수록** 좋은 기록 |
| 🃏 카드 짝맞추기 메모리 게임 | 카드를 뒤집어 같은 짝 찾기 | 점수 — 클수록 좋은 기록 |
| 🎯 타겟 클릭 슈팅 게임 | 무작위로 옮겨다니는 타겟을 클릭 | 점수 — 클수록 좋은 기록 |
| 🗝️ 텍스트 방탈출 / 심리테스트 | 선택지에 따라 스토리가 분기 | 선택 횟수 — **작을수록** 좋은 기록 |

!!반응속도·선택 횟수처럼 숫자가 작을수록 좋은 기록인 경우, AI에게 이 기준을 먼저 알려줘야 한다.!! 알려주지 않으면 AI가 습관적으로 "큰 값 = 최고 기록"으로 처리해버린다.

## 🗄 브라우저의 비밀 서랍 — localStorage

실습 중에 AI에게 "점수 안 날아가게 해줘"라고 요청해본 사람은 코드에 `localStorage`라는 단어가 등장하는 것을 봤을 것이다. 이것이 바로 ==브라우저 안에 있는 '현재 로그인된 내 브라우저 프로필 전용 비밀 서랍'==이다. 컴퓨터를 껐다 켜도, 브라우저를 닫아도 이 서랍 속 기록은 그대로 남는다.

### 동네 오락실 비유

```
로컬 저장소 (localStorage)   = 동네 오락실 게임기 1대
  - 그 기계, 그 브라우저 프로필에서 플레이한 기록만 남는다
  - 같은 PC라도 다른 계정이나 옆 컴퓨터에는 내 기록이 안 보인다

온라인 중앙 서버 (클라우드 DB) = 전 세계가 함께 겨루는 온라인 랭킹
  - 수천 명이 각자 자기 기기로 플레이해도 중앙 서버로 점수가 모인다
  - 모든 사람의 점수가 한곳에 모여 실시간 전체 랭킹이 완성된다
```

### 직접 확인해보기 — 새 창 vs 시크릿 창

1. **평범한 새 창**(`Ctrl+N`)을 하나 더 열고 같은 게임 파일을 열어본다 → ==최고 기록이 그대로 있다.== (같은 프로필 = 같은 서랍)
2. **시크릿 창**(`Ctrl+Shift+N`)이나 다른 계정으로 같은 파일을 열어본다 → 기록이 없다. 처음 상태로 돌아가 있다.

서랍을 나누는 기준은 **창이 아니라 브라우저 프로필**이다. 같은 프로필이면 창을 몇 개 열든 같은 서랍을 쓰고, 프로필이 달라지면(시크릿 창·다른 계정·다른 컴퓨터) 서랍도 통째로 달라진다. 그래서 다른 사람의 기록과 한곳에서 겨루는 ==진짜 온라인 랭킹을 만들려면 중앙 온라인 서버(클라우드 DB)가 필요==하다 — 5회차에서 다룬다.

## 🚀 실습 — 최고 기록 저장 기능 붙이기

```prompt
지금 만든 게임에 최고 점수 영구 저장 기능을 추가해줘.

1. 먼저 내 게임에서 '좋은 기록'의 기준을 확인해줘. 점수형(높을수록 좋음)이면 더 큰 값을, 반응속도·선택 횟수처럼 작을수록 좋은 기록이면 더 작은 값을 최고 기록으로 판정해야 해.
2. 이번 기록이 역대 최고 기록보다 좋으면, 새로고침(F5)을 하거나 창을 닫아도 지워지지 않게 브라우저 저장소(localStorage)에 보존해줘.
3. 게임 화면 상단에 [🏆 최고 기록] 라벨을 항상 띄워주고, 새로고침을 해도 이 기록이 계속 화면에 유지되게 해줘.
4. [최고기록 초기화] 작은 버튼을 만들어 누르면 저장된 기록이 지워지게 해줘.
5. 기존에 잘 작동하는 게임 로직과 디자인을 훼손하지 말고 안전하게 반영해줘.
```

저장을 붙인 뒤에는 ==일부러 나쁜 기록을 한 판 내보고, 최고기록이 바뀌지 않는지 반드시 확인==한다.

### 기능을 추가할 때마다 붙이는 안전 꼬리표

AI에게 기능 추가를 요청할 때는 항상 아래 문장을 함께 보낸다. AI가 새 코드를 넣으면서 기존 코드를 엉뚱하게 지워버리는 사고를 막기 위해서다.

```prompt
기존에 잘 작동하는 게임 로직과 디자인을 절대 훼손하거나 삭제하지 말고, 지금 만든 게임에 [추가할 기능]을 안전하게 추가해서 반영해줘.
```

## 🏆 심화 도전

### 1~3위 명예의 전당

```prompt
지금 만든 게임에 역대 상위 3위까지 기록되는 [명예의 전당] 기능을 달아줘.

1. 게임이 끝날 때마다 기록과 플레이 날짜를 브라우저에 저장해줘. 정렬 기준은 내 게임에 맞춰줘 — 점수형이면 큰 값이 1위, 반응속도·선택 횟수처럼 작을수록 좋은 기록이면 작은 값이 1위야.
2. 게임 화면 아래에 [🏆 명예의 전당 (Top 3)] 표를 만들어서 1위, 2위, 3위의 기록과 날짜를 보여줘.
3. [기록 초기화] 버튼을 만들어서 누르면 명예의 전당 기록이 모두 지워지게 해줘.
4. 기존 코드를 생략하거나 훼손하지 말고 안전하게 반영해줘.
```

### 다른 컴퓨터로 기록 옮기기 — JSON 백업 & 복원

서버가 없는 지금 상태에서 기록을 다른 PC나 다른 계정으로 옮기고 싶다면, ==세계 공용 데이터 포장지인 JSON 파일==로 내보내면 된다.

```prompt
지금 만든 게임에 [JSON 기록 백업 및 가져오기] 기능을 추가해줘.

1. 화면에 [기록 내보내기] 버튼을 만들어 누르면, 브라우저에 저장된 최고 점수 기록이 'score_backup.json' 파일로 즉시 다운로드되게 해줘.
2. [기록 가져오기] 파일 선택 버튼을 만들어, 다른 컴퓨터나 다른 계정에서 저장해 둔 JSON 파일을 업로드하면 점수가 그대로 복원되어 화면에 뜨게 해줘.
3. 기존 게임 화면과 플레이 동작을 훼손하지 말고 안전하게 반영해줘.
```

다른 도전 과제: 최고기록 갱신 시 화면 가득 축하 폭죽 연출 추가하기, 스마트폰 화면에서도 깨지지 않게 반응형으로 다듬기.

## 🔎 완성한 뒤 — 나 혼자 하는 QA

만든 사람은 늘 자기가 의도한 순서대로만 눌러본다. 일부러 규칙을 벗어난 조작을 해야 진짜 결함이 드러난다.

| 시나리오 | 무엇을 하는가 | 통과 기준 |
|---|---|---|
| 정상 흐름 | 시작 → 플레이 → 종료 → 결과 화면 → 다시 시작 | 어느 단계에서도 끊기지 않는다 |
| 엉뚱한 조작 | 시작 전에 게임판 누르기 / 시작 버튼 연타 / 도중 새로고침 | 화면이 깨지거나 점수가 이상해지지 않는다 |
| 기록 보존 | 기록을 세운 뒤 F5, 또는 창을 완전히 닫았다 다시 열기 | 최고 기록이 그대로 남아있다 |

### AI에게 "처음 쓰는 사용자" 역할을 맡기기

```prompt
너는 이제 내 게임을 처음 써보는 사용자야. 내가 만든 게임 파일을 읽고, 아래 3가지 관점에서
'처음 쓰는 사람이라면 어디서 헷갈리거나 잘못 누를지'를 찾아줘.

1. 설명 없이 화면만 봤을 때, 무엇을 먼저 눌러야 할지 바로 알 수 있는가?
2. 규칙을 모르는 사람이 엉뚱하게 조작하면(시작 전에 누르기, 버튼 연타, 도중 새로고침) 어떤 문제가 생기는가?
3. 게임이 끝난 뒤 무엇을 해야 하는지 화면이 알려주는가?

각 항목마다 [발견한 문제]와 [고치는 방법]을 짧게 적어주고, 코드는 아직 고치지 말고 목록만 먼저 보여줘.
```

AI가 내놓은 목록을 전부 받아들일 필요는 없다. 남은 시간과 중요도를 보고 1~2개만 골라 수정을 지시하면 된다. 무엇을 고치지 않기로 했는지도 판단의 일부다.

### 작업 일지 자동 생성

```prompt
오늘 나와 나눈 대화 전체를 돌아보고, 오늘 만든 게임 파일과 같은 폴더에 day03_log.md 파일을 만들어줘.

[진행 과정] 오늘 어떤 게임을 골라 어떤 순서로 만들었는지, 어떤 기능을 어떤 순서로 붙였는지
[결과 및 주요 판단] 중간에 무엇을 선택하고 무엇을 빼기로 했는지, 에러가 났다면 어떻게 해결했는지
[배운 점/인사이트] 오늘 처음 알게 된 개념을 내 언어로 정리
[다음 실습에 적용할 나만의 원칙] 내일부터 AI에게 요청할 때 지킬 규칙 3가지

각 영역은 3~5줄로 짧게 쓰고, 전문 용어에는 괄호로 쉬운 설명을 덧붙여줘.
```

생성 후에는 반드시 직접 읽고, 사실과 다른 부분이 있으면 그 자리에서 고친다.

## ✅ 오늘의 핵심 정리

1. **점진적 빌드** = 한 번에 다 시키지 않는다. MVP → 1기능씩 추가 → 저장/연출 순으로 쌓는다.
2. **레이지 프롬프팅** = 에러가 나면 해석하려 하지 말고, 콘솔의 빨간 에러 원문을 그대로 AI에게 전달한다.
3. **localStorage** = 내 브라우저 프로필 전용 서랍. 다른 사람과 공유하려면 중앙 서버가 필요하다.
4. **안전 꼬리표** = 기능을 추가할 때마다 "기존 코드는 훼손하지 말고"를 함께 요청한다.
