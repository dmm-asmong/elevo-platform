# 6회차 — 공공데이터 API로 축제 검색 MVP 만들기

> **오늘의 핵심 메시지:** ==진짜 데이터를 가져오되, 인증키는 절대 코드에 남기지 않는다.==

---

## 🔄 오늘은 반대 방향이다

5회차에서는 내 화면에서 구글 시트로 데이터를 **보냈다**. 오늘은 반대로 정부·공공기관이 관리하는 진짜 데이터를 인터넷에서 **가져와서** 화면에 보여준다.

```text
5회차: 내 화면 → Apps Script → Google Sheets   (보내기)
6회차: 내 화면 → 서버 함수 → 공공데이터 API    (가져오기)
```

오늘 완성하는 것은 지역·기간·키워드로 전국 축제를 검색하는 웹앱이다. 배포 절차는 4회차에서 이미 익혔으니, 오늘은 **실제 데이터 연결과 보안**에 집중한다.

### 📖 용어 정리

| 용어 | 쉬운 풀이 |
|------|-----------|
| **공공데이터** | 정부·지자체·공공기관이 업무 중 만들거나 모은 자료를, 법에 따라 국민이 쓸 수 있게 열어 둔 것. 축제 정보, 날씨, 버스 도착 시간 등 |
| **API** | 정해진 방식으로 데이터를 요청하고 받는 창구. 식당의 메뉴판+주문 창구에 비유할 수 있다 |
| **인증키** | 누가 얼마나 요청하는지 확인하려고 발급하는 디지털 출입증. 유출되면 다른 사람이 내 호출 한도를 쓸 수 있다 |
| **JSON** | 데이터를 주고받기 위한 텍스트 형식. `{"title": "축제명"}`처럼 키와 값의 쌍으로 이루어진다 |

## 🍽 API를 식당에 비유하면

| 식당에서 | API에서 | 오늘 실습의 예 |
|---|---|---|
| 메뉴판 | 주문할 수 있는 기능·조건 안내 | 한국관광공사 활용매뉴얼 |
| 주문 창구 | API 기능별 요청 주소(엔드포인트) | `searchFestival2` |
| 주문서 내용 | 요청에 붙이는 조건(파라미터) | 지역·시작일·종료일·키워드 |
| 회원 확인 | 인증키 | 공공데이터포털에서 발급한 내 키 |
| 나온 음식 | 응답 데이터 | 축제 목록 JSON |

요청 주소는 아래처럼 생겼다. `?` 뒤부터 조건이고, 조건끼리는 `&`로 잇는다.

```text
https://apis.data.go.kr/B551011/KorService2/searchFestival2   ← 기능 주소
?serviceKey=●●●●                                              ← 인증키 (화면에 보이면 안 됨)
&_type=json                                                    ← 응답 형식
&eventStartDate=20260901&lDongRegnCd=11                        ← 검색 조건
```

==이 주소를 직접 입력할 일은 없다.== 서버 함수가 화면의 검색 조건을 받아 이 주소를 대신 만든다.

## 📦 응답 JSON, 택배 상자로 이해하기

공공데이터 API가 돌려주는 JSON은 세 겹 상자 구조다.

| 구성 계층 | 택배 상자 비유 | 역할 |
|---|---|---|
| `response` | 전체 택배 상자 | 응답 전체를 감싸는 가장 바깥 객체 |
| `header` | 운송장 | `resultCode`가 `"0000"`이면 정상, 다른 코드면 오류 |
| `body` | 상자 속 내용물 | `items.item[]`(축제 목록), `totalCount`(전체 개수) |

축제 하나는 20여 개 필드를 갖고 있지만, 오늘 카드에는 !!다섯 개 핵심 필드만!! 골라 쓴다.

| 필드 | 화면 표시 | 비어 있을 때 |
|---|---|---|
| `title` | 축제명 | "이름 없는 축제" |
| `eventstartdate` / `eventenddate` | 기간 | "일정 미정" |
| `addr1` | 개최 장소 | "주소 정보 없음" |
| `firstimage` | 대표 이미지 | 대체 이미지 |
| `tel` | 문의처 | 표시 생략 |

지도 좌표, 분류 코드, 등록일시 같은 나머지 필드는 화면에서 쓰지 않는다. 서버 함수가 복잡한 원본에서 이 다섯 필드만 정리해서 화면에 건네준다.

## 🔒 인증키는 어디에 있어야 하는가

인증키가 새는 경로는 셋뿐이다. 셋 다 막는다.

| 노출 경로 | 막는 방법 |
|---|---|
| `index.html` | 키 값과 외부 API 전체 주소를 절대 넣지 않는다 |
| GitHub | `.gitignore`에 `.env`, `.env.local`, `.vercel`을 넣어 추적 대상에서 뺀다 |
| 브라우저 응답 / 서버 로그 | 화면에 필요한 다섯 필드만 반환하고, 키가 포함된 주소를 로그에 남기지 않는다 |

키가 머무는 흐름은 이렇게 정리된다.

```text
내 화면 (index.html, 키 없음)
  → 서버 함수 (api/festivals.js, 환경변수로만 키를 읽음)
    → 공공데이터 API
```

> !!핵심: 코드 어디에도 실제 키 문자열을 타이핑하지 않는다.!! 서버 함수에는 `process.env.DATA_GO_KR_API_KEY`라는 **환경변수 이름**만 쓴다. 실제 키 값은 Vercel의 환경변수 설정 화면에만 입력한다.

GitHub에 올라간 코드는 전 세계에서 자동으로 스캔되어, 노출된 키는 금방 도용될 수 있다. 코드에 키가 보이면 즉시 지우고, 이미 공개됐다면 포털에서 키를 폐기하고 재발급한다.

## 🚀 실습 — 매뉴얼 분석부터 배포까지

### STEP 1. 매뉴얼을 AI와 함께 분석하기

내가 먼저 다 읽고 요약하지 않는다. 공식 매뉴얼 파일을 첨부하고 AI에게 구조부터 정리시킨다.

```prompt
첨부한 한국관광공사 개방데이터 활용매뉴얼을 분석해 주세요.

아직 웹앱을 추천하거나 코드를 만들지 마세요.

다음 내용을 매뉴얼 근거에 따라 초보자가 이해하기 쉬운 말로 정리해 주세요.

1. 이 API로 제공받을 수 있는 정보
2. 사용할 수 있는 주요 기능 주소
3. 각 기능의 필수 입력값과 선택 입력값
4. 응답에서 화면에 사용할 수 있는 주요 필드
5. API 키가 필요한 위치와 공개하면 안 되는 이유
6. 매뉴얼만으로 확인할 수 없는 내용

추측하지 말고 매뉴얼의 기능명과 항목명을 근거로 설명해 주세요.
코드는 만들지 마세요.
```

**바로 확인할 것:** 기능명과 파라미터가 매뉴얼과 일치하는가? 필수 입력과 선택 입력이 구분되어 있는가? 문서에 없는 내용을 사실처럼 단정하지 않았는가?

### STEP 2. 웹앱 아이디어 추천받고 목표 확정하기

### STEP 3-A. 샘플 데이터로 화면 먼저 만들기

실제 API를 연결하기 전에 화면부터 완성한다. 이렇게 순서를 나누면, 나중에 문제가 생겨도 "화면이 문제인지" "연결이 문제인지" 바로 구분할 수 있다.

```prompt
지금까지 분석하고 합의한 내용을 바탕으로 축제 검색 웹앱의 화면을 먼저 만들어 주세요.

[화면]
- 화면 코드는 index.html 한 파일로 작성
- 지역, 시작일, 종료일, 키워드 검색 입력
- 검색 결과는 카드 목록으로 표시
- 카드에는 축제명, 주소, 기간, 대표 이미지 표시
- 검색 전, 결과 없음 상태 구분
- 모바일에서도 가로 스크롤 없이 사용 가능

[샘플 데이터]
- 프로젝트 폴더의 mock_festivals.json을 샘플 데이터로 사용
- 더블클릭으로 열어도 동작하도록 index.html 안에 같은 데이터를 넣기

[이번에 만들지 않음]
- 실제 API 연결과 서버 함수(api/festivals.js)
- 지도, 로그인, 즐겨찾기, 데이터베이스, 상세 페이지

먼저 생성할 파일과 구현 순서를 설명하고 제 검토를 기다려 주세요.
```

계획을 확인했다면 실행을 승인한다.


### STEP 3-B. 같은 화면에 실제 API 연결하기

화면과 카드 코드는 그대로 두고, 데이터를 가져오는 부분만 서버 함수로 바꾼다.

```prompt
샘플로 확인한 index.html 화면에 실제 공공데이터를 연결해 주세요.

[서버 함수]
- api/festivals.js 서버 함수 생성
- DATA_GO_KR_API_KEY는 서버 함수에서 환경변수로만 읽기
- 지역과 기간은 searchFestival2 요청에 반영
- 키워드는 받아온 축제의 제목과 주소에서 필터링
- 응답은 샘플과 같은 title, address, startDate, endDate, image 다섯 필드로 정리

[화면 연결]
- index.html에 실제 API 검색 버튼을 추가하고 /api/festivals만 호출
- 기존 샘플 검색과 카드 화면은 그대로 유지
- 불러오는 중, 오류 상태 추가
- index.html에는 실제 키와 외부 API 전체 주소를 넣지 않기

먼저 생성하거나 수정할 파일과 구현 순서를 설명하고 제 검토를 기다려 주세요.
```

**승인 전 확인할 것:** 코드에 키 값이 아니라 `DATA_GO_KR_API_KEY`라는 이름만 쓰였는가? 서버 함수 응답이 샘플과 같은 다섯 필드 구조인가? 기존 샘플 검색 기능을 건드리지 않았는가?

### STEP 5. Vercel 환경변수 등록과 배포 확인

1. Vercel 프로젝트 → **Settings → Environment Variables**로 이동한다.
2. Name에 `DATA_GO_KR_API_KEY`, Value에 내 인증키를 입력한다.
3. **Production**을 선택하고 저장한 뒤, 새로 배포(Redeploy)한다.

> ==환경변수는 이전 배포에 자동으로 적용되지 않는다.== 값을 저장하거나 바꾼 뒤에는 반드시 새로 배포해서 확인한다.

배포 후에는 `result: success`와 `items` 배열이 정상적으로 오는지, 날짜를 잘못 입력했을 때 오류 안내가 뜨는지, 결과가 없을 때 "오류"가 아니라 "결과 없음"으로 구분되는지 확인한다.

```prompt
- 지역·기간·키워드 검색이 계속 작동
- index.html에 API 키를 넣지 않음
- 기존 결과 카드와 오류 상태를 깨뜨리지 않음
```

수정 후에는 지역·기간·키워드 검색이 여전히 작동하는지, 키가 어디에도 노출되지 않았는지 다시 확인하고 두 번째로 push·배포한다.

## ✅ 오늘의 핵심 정리

1. **공공데이터 API** = 정부·공공기관의 진짜 데이터를 정해진 방식으로 요청해서 받는 창구다.
2. **인증키는 절대 코드에 쓰지 않는다.** 서버 함수에서 환경변수 이름으로만 읽는다.
3. **화면 → 서버 함수 → 외부 API** 3단 구조를 지키면, 브라우저에는 키가 전혀 노출되지 않는다.
4. **샘플로 화면을 먼저 완성한 뒤 실제 데이터를 연결한다.** 문제가 생겼을 때 원인을 훨씬 빨리 좁힐 수 있다.
5. **결과 없음과 오류는 다르다.** 조건에 맞는 축제가 없는 것은 정상이고, API 요청 자체가 실패한 것은 오류다.
