기초 개념 ① 공공데이터

공공데이터는 공공기관이 모두에게 열어 둔 자료입니다

정부·지자체·공공기관이 업무를 하며 만들거나 모은 전자 자료를, 법에 따라 국민이 활용할 수 있게 개방한 것입니다.

법의 정의 · 공공데이터법 제2조
공공기관이 법령에서 정한 목적으로 만들거나 취득해 관리하는, 전자적 방식으로 처리된 자료·정보

예: 축제·관광지 정보, 날씨 예보, 버스 도착 시간, 인구 통계, 약국 위치

기초 개념 ③ 인증키

인증키는 나에게만 발급된 이용 열쇠입니다

기관은 인증키로 누가 얼마나 요청하는지 확인하고, 한 사람이 너무 많이 호출하지 않도록 한도를 둡니다.

01
활용신청을 하면 발급됩니다

관광공사 서비스는 개발계정 자동승인, 하루 1,000회까지 호출할 수 있습니다.

02
마이페이지에 키 1개가 보입니다

%2B처럼 %가 섞인 긴 문자열입니다. 형태 변환은 서버 코드가 처리합니다.

03
비밀번호처럼 다룹니다

채팅·index.html·GitHub에 붙이면 다른 사람이 내 호출 한도를 써 버릴 수 있습니다.

키가 머무는 곳
브라우저 화면에는 키가 없습니다
  • 내 화면 index.html → 키 없이 /api/festivals에 요청
  • 서버 함수 api/festivals.js → 환경변수 DATA_GO_KR_API_KEY에서 키를 꺼냄
  • 공공데이터 API → 키를 확인하고 축제 목록을 돌려줌
기초 개념 ④ JSON

JSON은 데이터를 주고받기 위한 텍스트 형식입니다

화면 모양을 저장하는 파일이 아니라, 이름과 값을 일정한 규칙으로 묶어 둔 데이터입니다.

JSON에서 보는 기호
{ } 관련된 이름과 값을 묶는 객체
[ ] 여러 항목을 순서대로 담는 배열
"이름": 값 키와 값 한 쌍
기본 작성 규칙
  • 문자열과 키 이름은 큰따옴표로 감싼다.
  • 항목 사이는 쉼표로 구분한다.
  • 마지막 항목 뒤에는 쉼표를 붙이지 않는다.
  • 값은 문자·숫자·참/거짓·null·객체·배열이 될 수 있다.
예시
{ "title": "도산 안창호의 날 기념행사", "addr1": "서울 강남구 도산대로 320" }
같은 내용을 XML은 <title>…</title> 태그로 감쌉니다. 관광공사 API는 둘 다 제공하므로 _type=json으로 JSON을 요청합니다.
구분
HTML은 화면의 구조를 만들고, JSON은 화면에 채울 데이터를 전달합니다.

실제 API 응답 구조

공공데이터는 택배 상자 3겹으로 포장되어 옵니다

header(운송장)로 배달 성공을 확인하고, body(상자 안 내용물)에서 축제 목록을 꺼냅니다.

📦 공공데이터 실제 응답 형태
response {
📋 "header": {
"resultCode": "0000" /* 성공 */
},
📦 "body": {
"items": { "item": [ ... ] },
"totalCount": 1 /* 전체 개수 */
}
}
운송장 확인
resultCode: "0000" (정상 성공)

서버의 배달 성공 신호입니다. 0000이 아니라면 인증키 오류나 필수 입력 누락을 알리는 신호입니다.

상자 속 내용물
body.items.item [ ] 축제 배열

축제명·기간·장소·이미지가 담긴 배열입니다. 첫 번째 축제는 item[0], 배열 번호는 0부터 셉니다.

오류 코드

오류 코드는 다음 확인 지점을 알려줍니다

코드 뜻 다음 확인
INVALID_REGION 지원하지 않는 지역 지역 선택값
INVALID_DATE_RANGE 날짜 형식·순서 오류 시작일과 종료일
MISSING_API_KEY 환경변수 누락 이름·Production·재배포
UPSTREAM_AUTH_ERROR 외부 API 인증 문제 활용신청과 키 종류
UPSTREAM_RATE_LIMIT 호출량 제한 반복 호출 중지 후 재시도
UPSTREAM_RESPONSE_ERROR 외부 응답 문제 Function 로그·기관 공지
