PART 00 · 지금 방식의 한계

파일 이름으로 버전을 관리하면 여기서 막힙니다

2·3일차 작업물을 저장해 온 방식을 그대로 떠올려 봅니다.

소개.html → 소개_수정.html → 소개_진짜최종.html

어느 것이 최신인지 파일 이름만으로는 판단할 수 없습니다.

무엇이 왜 바뀌었는지 남지 않습니다

파일은 남아도 바꾼 이유는 며칠 뒤 본인도 기억하지 못합니다.

이전 상태로 정확히 되돌릴 수 없습니다

덮어쓴 뒤에는 되돌릴 기준점 자체가 사라집니다.

남에게 보여줄 주소가 없습니다

파일을 첨부하는 방식은 고칠 때마다 최신본을 다시 보내야 합니다.

SOLUTION
변경마다 되돌릴 수 있는 지점을 이유와 함께 남긴다

그 기록을 온라인에 두고, 기록을 그대로 공개 주소로 바꾸는 것이 오늘 하는 일입니다.

PART 00 · Git과 GitHub의 차이

Git은 기록하는 도구, GitHub은 그 기록을 올려두는 곳

이름이 비슷해 자주 섞이지만 하는 일이 다릅니다.

GIT · 2005
파일 변경을 추적하는 버전 관리 도구

내 컴퓨터에서 동작하는 프로그램입니다.
언제 무엇을 왜 바꿨는지를 저장 지점으로 남깁니다.
인터넷 연결 없이도 기록할 수 있습니다.

GITHUB · 2008
Git 프로젝트를 클라우드에 올려두는 플랫폼

저장소(repository)를 온라인에 보관합니다.
여기에 협업 도구와 배포 연결이 더해집니다.
주소가 생기므로 누구에게든 보여줄 수 있습니다.

🔗
GitHub 없이 Git은 쓸 수 있지만, Git 없이 GitHub은 쓸 수 없습니다. 오늘 쓰는 commit·push·revert는 모두 Git의 기능이고, GitHub은 그 결과가 도착하는 장소입니다.
가입 vs 설치 — 다른 일입니다

가입은 계정, 설치는 프로그램

오늘 두 가지가 모두 필요합니다. 하나는 이미 끝났습니다.

DONE · 가입
GitHub 계정

인터넷 서비스의 계정입니다. GitHub 회사의 서버에 만들어집니다.

NEEDED · 설치
Git 프로그램

내 노트북에서 실행되는 프로그램입니다. 계정을 만들었다고 함께 설치되지 않습니다.

WHY
Codex 안에 Git이 들어 있지 않습니다

Codex는 내 컴퓨터의 git 명령을 대신 실행할 뿐입니다. 기록하고 보내는 실제 작업은 Git이 합니다.

✓
확인 방법은 한 줄입니다. git --version 을 실행해 버전 번호가 나오면 준비가 끝난 것입니다.

PART 02 · 사람이 확인

“올라갔다”가 아니라 무엇이 올라갔는지 확인

GitHub 저장소 화면에서 다음 다섯 항목을 직접 봅니다.

  • 주소의 사용자 이름과 -manual 저장소명이 맞다.
  • 공개 범위가 Public이다.
  • index.html과 README.md만 있다.
  • 두 파일을 열면 내용이 정상이다.
  • 첫 커밋 메시지가 보인다.
  • 비밀정보와 개인정보가 없다.

PART 06 · 안전한 복구 원칙

복구는 기록 삭제가 아니라 되돌림 기록 추가

git revert는 잘못된 변경을 반대로 적용한 새 커밋을 만듭니다.

위험한 생각

“최근 기록을 지우고 강제로 이전 상태로 덮자”

오늘의 방식

오류 커밋 ID를 확인하고, 그 커밋만 되돌리는 새 기록을 남깁니다.

왜 안전한가?

무엇을 되돌렸는지 기록이 남고, GitHub와 Vercel의 변경 흐름도 이어집니다.
